# scripts ディレクトリ仕様

この README は scripts ディレクトリの仕様書である。

ルールとスキルの言語版を処理するスクリプトを置く。正本は `rules.ja/` と `skills.ja/` で、他の版（例えば `rules.en/` と `skills.en/`）は翻訳スクリプトが正本から生成する。`build-rules`、`install-rules`、`install-skills`、`translate-rules`、`translate-skills` は実装済み。

| スクリプト | 仕事 |
|---|---|
| `build-rules` | `--lang` で選んだルール版から配布物（Cursor 版／Claude 版）を決定的に生成する |
| `install-skills` | `--lang` で選んだ版のスキルを、ホームのスキル置き場へシンボリックリンクとして配置する |
| `install-rules` | `build-rules` が書いた配布物を、ホームのルール置き場へシンボリックリンクとして配置する |
| `translate-rules` | ルール版 `rules.<from>/` を `rules.<to>/` へ翻訳する（既定は正本から英語版） |
| `translate-skills` | スキル版 `skills.<from>/` を `skills.<to>/` へ翻訳する（既定は正本から英語版） |

## build-rules

目的：`rules.<lang>/<名前>/` の `body.md` と `meta.json` から、`.cursor/rules/<名前>.mdc` と `.claude/rules/<名前>.md` を生成する。`<lang>` は `--lang` で選ぶ言語である。

入出力の契約：

- 入力は選択した版のみ。出力は入力の純粋な関数であり、同じ入力からは常に同じバイト列が出る（冪等）
- 生成物には目印のヘッダを付けない。正本とのズレはファイル内の文言ではなく `--check` で検出する
- `--check` は書き込まず、生成物と選択した版の一致だけを検査し、ズレたファイル名を示して異常終了する
- `--lang <言語>` は入力の版 `rules.<言語>/` を選び、既定は `en` である。言語を一覧で照合することはしない。その版のディレクトリが存在する言語なら生成できる。言語コードは英字・数字・`-`・`_` だけで書く（値は版ディレクトリ名の一部になるため、リポジトリの外へ出る値を防ぐ）。合わない値は、版ディレクトリを見る前に `lang: "<値>" is not a language code. pass --lang with letters, digits, - or _, such as en or ja` で異常終了し、何も変えない。`--lang` を2回以上渡すと、何かを読む前・書く前に `lang: --lang was given more than once. pass it once` で異常終了する。生成物には、どの言語から作ったかが記録されない。したがって生成と配置は、同じ言語で続けて行う
- 報告も契約の一部である。通常実行は、何をしたかを標準出力に出す：要約行（`wrote <件数> files from rules.<lang> under <ルート>`）に続けて、書き込んだ全ファイルのパスを出す。`--check` の成功時は `checked <件数> files from rules.<lang> under <ルート>; all match; wrote nothing` に続けて、検査した全パスを出す。無言の成功は欠陥である：何も起きなかったことと区別できない
- `--check` の失敗時は、標準エラーに要約行、問題ごとの行、次のアクション（`run without --check to write them.`）を出す。ズレたファイルと欠けたファイルは個別に名前を出す（`differs: <パス>`、`missing: <パス>`）。出力ディレクトリ自体が無い・空の場合は、配下のファイルを列挙せず、ディレクトリを一度だけ名指す（`missing: <ディレクトリ>`、`empty: <ディレクトリ>`）。空とは、ディレクトリにエントリが1つも無いことである。ディレクトリが存在し、無関係なファイルを含め何かが入っている場合は空ではなく、欠けた生成物をそれぞれ `missing: <パス>` で名指す。問題は、オペレータが操作する単位で報告する

非目標：翻訳、ホームへの配置、git 操作、監視モード、増分処理。

変換表（正本の `meta.json` は `description` と `cursor` 名前空間を持つ）：

| meta.json | Cursor 版（.mdc） | Claude 版（.md） |
|---|---|---|
| `cursor.alwaysApply: true` | frontmatterに `alwaysApply: true` | frontmatterなし |
| `cursor.globs` あり | frontmatterに `globs` | frontmatterに `paths` として出力 |
| それ以外（description のみ） | frontmatterに description のみ | frontmatterなし |

注：Claude Code のルール読み込みはfrontmatterの `paths` のみを見て、`alwaysApply` は読まない。`~/.claude/rules/` に置かれたファイルは常駐ロードされる。auto（description のみ）のルールをホーム側でどう扱うかは install 設計の未決事項（実測による確認待ち）。

検証とエラー：

- 全ルールの検証を終えてから書き始める。`meta.json` は object であり、`description` は文字列、`cursor` は object である。未知キーはトップレベルと `cursor` の中の両方で拒否する。`cursor.globs` があるときは文字列か null であり、null は globs なしを意味する。`cursor.alwaysApply` があるときは真偽値である。`body.md` が存在すること。不正が1件でもあれば異常終了し、出力ファイルは書かれない
- `rules.<lang>` 自体が無いときも異常終了し、何も書かない
- エラー表示はルール名・原因・次のアクションの形。`rules.<lang>` が無いときは、同じ形で名前を `rules.<lang>` とする。終了コードで成否を返す

実装：Python 3、標準ライブラリのみ、拡張子なしのスクリプトファイル。対象のリポジトリはスクリプトのあるリポジトリであり、他を指すオプションは無い。ルールの読み込みと検証は `scripts/rule_source.py` にあり、translate-rules と共有する。これにより、ルールは両方で有効か両方で無効かのどちらかになり、エラー行も同じになる。スクリプトは自分のディレクトリからそれを読み込む。JSON は標準の `json` で読み、frontmatter の値はクォートなしの plain scalar で出力し、キー順は description、globs、alwaysApply として現行の .mdc に合わせる。Mac／Windows の両方で動くことを前提とする。

テスト：テストファーストで作る。フィクスチャ3ケース（alwaysApply／globs／description のみ）のゴールデン比較、実ルールの凍結スナップショットによる回帰（入力と期待出力を 2026-11-21 に `scripts/tests/fixtures/real/` へ凍結したもの。オラクルはスナップショットであり、現行の生成物ではない。スナップショットは日本語正本なので、この実行は `--lang ja` を渡す）、出力報告の検証（要約行の全文と、実行が書いた／検査した全パス）、`--check` のケース（一致、手編集、兄弟が残った状態でのファイル1件の欠落、出力ディレクトリの欠落・空、無関係なファイルだけが残るディレクトリ）、異常系（欠落・不正・未知キー、object でない `meta.json`、`description` の欠落・非文字列、`cursor` の欠落・非 object、`cursor` 配下の未知キー、非文字列の `globs`、非真偽値の `alwaysApply`、版ディレクトリの欠落、および正常と異常の混在で出力が書かれないこと）、および `--lang` のケース（既定では英語版を生成し、`--lang ja` で日本語版を生成し、繰り返した `--lang` は上の文面で異常終了して何も書かないこと）。テスト対象のスクリプトは、各フィクスチャリポジトリの `scripts/` へコピーして、そこから実行する。

完了条件：

1. 実ルールの凍結スナップショットに対して、生成物が期待出力とバイト単位で一致する
2. 2回連続実行で2回目の差分がゼロ
3. `--check` が、選択した版と一致する状態で正常終了し、生成物の手編集・ファイル欠落・出力ディレクトリの欠落／空で異常終了する。名前はズレたファイルを示し、ディレクトリ自体が無い、またはエントリが1つも無いときだけディレクトリを示す。無関係なファイルが残っているディレクトリはそれに当てはまらず、欠けた生成物をそれぞれ名指す
4. 不正な入力で異常終了し、出力ファイルを一切書かない
5. globs を持つフィクスチャで、Claude 版に `paths` frontmatterが正しく出る

## install-skills

目的：`skills.<lang>/<名前>/` のスキルを、ホームのスキル置き場（`~/.claude/skills/` と `~/.cursor/skills/`）へ、スキルごとに1つのシンボリックリンクとして配置する。リンク先はこのリポジトリ内のスキルディレクトリである。スキルには形式変換が無いため、配置はコピーを作らずリンクだけを作る：実ファイルはリポジトリ内の版だけにし、スキルの編集は再配置なしで効く。

入出力の契約：

- 配置の単位はスキルディレクトリである。リンクはその中身すべて（SKILL.md と補助ファイル）をカバーし、スキル内部にファイルが増えても再配置は不要である。再配置が要るのはスキル自体の追加・削除のときだけである
- リンク先は、スクリプトのあるリポジトリ配下の絶対パスである。リポジトリを移動するとリンクは壊れるが、`--check` がそれを報告し、通常実行が修復する
- このスクリプトが管理するのは、このリポジトリのスキル版（いずれかの言語の `skills.<lang>/` ディレクトリ）を指すシンボリックリンクだけである。実ファイル・実ディレクトリを作る・上書きする・消すことは決してせず、他を指すリンクにも触らない。他者のエントリ（例：`~/.claude/skills/synced/`。Claude Code が利用者の claude.ai アカウントからダウンロードしたスキルを置く場所）は管理対象外である
- このリポジトリの、選択した版とは違う版を指すリンクは、リンク先違いである。通常実行は選択した版へ修復し、`--check` は `differs` として報告する
- スキルの配置を妨げる宛先エントリ（実ファイル・実ディレクトリ、またはこのリポジトリの外を指すリンク）は衝突である。衝突は、何も変更する前に検出する：不正なスキルが1つでもある、または選択した宛先に衝突が1つでもあれば、異常終了し、リンクの作成・修復・除去は一切行わない
- 選択した宛先で、このリポジトリのスキル版のいずれかを指し、選択した版に存在しないスキルへのリンクは、残骸である。通常実行はこれを除去し、`--check` は報告する。除去するのは、このリポジトリ内を指すリンクだけである
- 報告も契約の一部である。通常実行は、要約行（`installed <件数> skills from skills.<lang> under <ホーム>`）に続けて、配置済みの全リンクのパスを出し、除去した残骸リンクごとに `removed: <パス>` の行を出す。`--check` の成功時は `checked <件数> links from skills.<lang> under <ホーム>; all match; wrote nothing` に続けて、検査した全パスを出す。無言の成功は欠陥である：何も起きなかったことと区別できない
- `--check` の失敗時は、標準エラーに要約行、問題ごとの行、次のアクション（`run without --check to install the links; conflicting entries must be removed by hand.`）を出す。問題は、オペレータが操作する単位で名前を出す：エントリが無い場合は `missing: <パス>`、リンク先が違う・壊れている場合は `differs: <パス>`、スキルが消えたリンクは `stale: <パス>`、触ってはいけない妨害エントリは `conflict: <パス>`。宛先ディレクトリ自体が無い場合は、配下のリンクを列挙せず、ディレクトリを一度だけ名指す（`missing: <ディレクトリ>`）
- 2回連続実行では、2回目は何も変わらない（冪等）
- `--tool <cursor|claude>` は、実行の対象を一方の宛先に絞る。`cursor` は `<ホーム>/.cursor/skills`、`claude` は `<ホーム>/.claude/skills` である。`--tool` を省くと両方の宛先が選ばれ、これが上のすべての場合である。選ばれなかった宛先はこの実行の対象外である：作らない、中を見ない、報告しない。そこにある衝突や残骸リンクは実行に影響せず、失敗した実行を含め、前後で同一である。`cursor` と `claude` 以外の値は `tool: unknown tool "<値>". pass --tool cursor or --tool claude` で異常終了する。`--tool` を2回以上渡したときは `tool: --tool was given more than once. pass it once` で異常終了する。どちらのエラーも、宛先を読む前・書く前に出し、何も変えない。要約の件数は、通常実行ではスキル数、`--check` ではリンク数のままである。宛先が一方だけのとき、この二つの数は一致し、表示するパスはすべて選択した宛先の下にある
- `--lang <言語>` は、配置する版 `skills.<言語>/` を選び、既定は `en` である。言語を一覧で照合することはしない。その版のディレクトリが存在する言語なら配置できる。言語コードは英字・数字・`-`・`_` だけで書く（値は版ディレクトリ名の一部になるため、リポジトリの外へ出る値を防ぐ）。合わない値は、版ディレクトリを見る前に `lang: "<値>" is not a language code. pass --lang with letters, digits, - or _, such as en or ja` で異常終了し、何も変えない。`--lang` を2回以上渡すと、宛先を読む前・書く前に `lang: --lang was given more than once. pass it once` で異常終了し、何も変えない

非目標：スキルファイルのコピー、ルールの配置（`install-rules` がリンクする）、実ファイル・実ディレクトリの削除、プラグインスキルや claude.ai 同期スキルの管理、監視モード、Windows 対応（シンボリックリンクに特権が要る環境は前提にしない）。

検証とエラー：

- 全スキルの検証を終えてからリンクを始める。`skills.<lang>` が存在すること。`skills.<lang>/` の各サブディレクトリがスキルであり、`SKILL.md` を含む。その frontmatter は単純な `key: value` 行として読み、`name` と `description` があり、どちらも空でない文字列で、`name` がディレクトリ名と一致すること。frontmatter のうち、空でないのにコロンの無い行、閉じ `---` の欠落、同じキーの重複は、読み飛ばしも上書きもせずエラーにする。他の frontmatter キーは許可する（スキル形式は開かれた標準で、`disable-model-invocation` のような任意キーがある）。`synced` という名前のスキル（大文字小文字を問わない）は、選択した宛先に `claude` が含まれるときに拒否する：Claude Code が `~/.claude/skills/` で同期スキル用に予約した名前である。`--tool cursor` だけのときは、その名前は通常のスキルである。全スキルが検証を通り、選択した宛先に衝突が無いときにだけリンクを始める
- エラー表示はスキル名・原因・次のアクションの形。`skills.<lang>` が無いときは、同じ形で名前を `skills.<lang>` とする。終了コードで成否を返す

実装：Python 3、標準ライブラリのみ、単一ファイル（拡張子なし）、build-rules と同じ流儀。コマンドラインは `install-skills [--home <ホームディレクトリ>] [--tool <cursor|claude>] [--lang <言語>] [--check]` で、対象のリポジトリはスクリプトのあるリポジトリ、`--home` は既定で利用者のホームであり、テストが一時ホームへ配置できるようにするためのものである。frontmatter は単純な `key: value` 行として読み、YAML ライブラリは使わない。対象プラットフォームは macOS である。

テスト：テストファーストで、build-rules のテストと同じ流儀（スクリプトを一時的なリポジトリの `scripts/` へコピーし、そこからサブプロセスとして、一時的な `--home` に対して実行する）。ケースは、新規配置で全スキルが両宛先に正しいリンク先で張られること、2回目の実行で何も変わらないこと、`--check` が配置済み状態で成功し、リンク欠落・リンク先違い・残骸リンク・衝突でパスを名指して失敗し、宛先ディレクトリの欠落ではディレクトリだけを名指すこと、通常実行が残骸リンクを除去しリポジトリ移動で壊れたリンクを修復すること、衝突（宛先の実ディレクトリ）が実行全体を止めて何もリンクされないこと、不正入力（SKILL.md 欠落、description の欠落・空、ディレクトリ名と違う name、frontmatter のコロンの無い行、閉じ `---` の欠落、キーの重複、`synced` という名前のスキル、`skills.<lang>` の欠落、正常と異常の混在）で異常終了して何も変わらないこと、スクリプトが所有しないエントリ（実在の `synced/` ディレクトリ、外を指すリンク、実ファイル）が、失敗した実行を含め全ての実行の前後で不変であること、出力報告の検証（要約行の全文と、実行が配置した／検査した全パス）、実物の `skills.<lang>` を一時ホームへ配置し、その版の全スキルがリンクされ、全リンクが SKILL.md を含むディレクトリへ解決すること（出力はバイト列ではなくリンクであるため、オラクルはゴールデンスナップショットではなく版自体である）、および `--tool` のケース（cursor のみと claude のみは、その宛先だけにリンクし、もう一方は不変であること、選ばれなかった側の衝突や残骸は実行を止めずそのまま残ること、修復と残骸の除去は選択した宛先だけであること、`--check` は選択した宛先だけを名指すこと、`synced` という名前は claude では拒否され cursor のみでは受け付けること、未知の値と繰り返した `--tool` は上の文面で異常終了し何も変えないこと）、および `--lang` のケース（既定では `skills.en` から配置し、`--lang ja` では `skills.ja` から配置すること、もう一方の版を指すリンクは選択した版へ修復されること、選択した版に無いスキルのリンクは残骸として除去されること、繰り返した `--lang` は上の文面で異常終了し何も変えないこと）。

完了条件：

1. `--tool` を省いたとき、空のホームに対して、選択した版（既定は `skills.en`）の全スキルが両宛先にリンクされ、全リンクがリポジトリ内のそのスキルディレクトリへ解決する
2. 2回連続実行で、2回目はリンクの作成・修復・除去を一切しない
3. `--check` が、配置済み状態で正常終了し、リンクの欠落・リンク先違い・残骸・衝突でパスを名指して異常終了し、宛先ディレクトリ自体が無いときだけディレクトリを名指す
4. 不正な入力または衝突があるとき、異常終了し、何も変えない：リンクの作成・修復・除去を一切しない
5. スクリプトが所有しないエントリ（実ファイル・実ディレクトリ、このリポジトリの外を指すリンク、`synced/`）は、失敗した実行を含め、全ての実行の前後で同一である
6. `--tool cursor` または `--tool claude` では、その宛先だけをリンクし、検査し、修復し、掃除する。もう一方の宛先は、失敗した実行を含め、前後で同一である。未知の値、または繰り返した `--tool` は、何も変えない

## install-rules

目的：`build-rules` がすでに書いた配布物（`.cursor/rules/<名前>.mdc` と `.claude/rules/<名前>.md`）を、ホームのルール置き場（`~/.cursor/rules/` と `~/.claude/rules/`）へ、ファイル1件につきシンボリックリンク1本で配置する。配置は生成せず、コピーもしない。ファイルはリポジトリ内の `.cursor/` と `.claude/` に置いたままにする。そこが `build-rules` の書き出し先である。

入出力の契約：

- ルールの集合は `rules.<lang>/` のサブディレクトリである。`<lang>` は `--lang` で選ぶ言語である。この実行がリンクする配布物は `build-rules` が書いたものである。配布物には、どの言語から作ったかが記録されない。したがって生成と配置は、同じ言語で続けて行う。選択した宛先ごとに、そのルールの配布物がすでに存在すること。配布物が無いときは `<名前>: missing <パス>. run build-rules` とし、その実行は何も変えない。他のルールの配布物が揃っていても同じである。配布物のファイル自体は変更しない
- リンク先は、スクリプトのあるリポジトリの下の絶対パスである。リポジトリを移すとリンクは切れる。`--check` はそれを報告し、通常実行は修復する
- スクリプトが管理するのは、`.cursor/rules/` または `.claude/rules/` の配布物を指すシンボリックリンクだけである。実ファイルや実ディレクトリは作らず、上書きせず、消さない。他を指すリンクには触らない
- ルールのファイルをふさぐ宛先のエントリ（実ファイル、実ディレクトリ、配布物を指さないリンク）は衝突である。衝突は何かを変える前に検出する。選択した配布物が欠けるか、選択した宛先に衝突があれば、異常終了し、リンクの作成・修復・除去はしない
- 選択した宛先にあり、`rules.<lang>/` にもう無いルールの配布物を指すリンクは残骸である。通常実行はリンクを除去し、`--check` は報告する。除去するのはそのようなリンクだけである。リポジトリ内の配布物ファイルは残す
- 報告は契約の一部である。通常実行は `installed <件数> files from rules.<lang> under <ホーム>` を出し、その後に存在する全リンクのパスを出す。除去した残骸リンクは `removed: <パス>` を1行ずつ出す。成功した `--check` は `checked <件数> links from rules.<lang> under <ホーム>; all match; wrote nothing` を出し、その後に検査した全パスを出す。無出力の成功は欠陥である。何も起きなかったことと区別できない
- 失敗した `--check` は、標準エラーに `links do not match rules.<lang>. --check changes nothing.`、問題1件につき1行、次のアクション（`run without --check to install the links; conflicting entries must be removed by hand.`）を出す。問題はオペレータが操作する単位で名指す。エントリが無いときは `missing: <パス>`、リンクが違う配布物を指すときは `differs: <パス>`、ルールが消えたリンクは `stale: <パス>`、触れてはならないエントリは `conflict: <パス>` である。宛先ディレクトリ自体が無いときは、そのディレクトリを1回だけ名指し（`missing: <ディレクトリ>`）、その下のリンクは列挙しない
- 2回連続実行では、2回目は何も変わらない（冪等）
- `--tool <cursor|claude>` は、実行の対象を一方の宛先に絞る。`cursor` は `<ホーム>/.cursor/rules`、`claude` は `<ホーム>/.claude/rules` である。`--tool` を省くと両方の宛先が選ばれる。選ばれなかった宛先はこの実行の対象外である：作らない、中を見ない、報告しない。そこにある衝突や残骸リンクは実行に影響しない。配布物を要求するのは選択した宛先だけである。`cursor` と `claude` 以外の値は `tool: unknown tool "<値>". pass --tool cursor or --tool claude` で異常終了する。`--tool` を2回以上渡したときは `tool: --tool was given more than once. pass it once` で異常終了する。どちらのエラーも、何かを読む前・書く前に出し、何も変えない。通常実行の件数はファイル数、`--check` の件数はリンク数である。宛先が一方だけのとき、この二つの数は一致し、表示するパスはすべて選択した宛先の下にある
- `--lang <言語>` は、この実行が使う版 `rules.<言語>/` を選び、既定は `en` である。言語を一覧で照合することはしない。その版のディレクトリが存在する言語なら選べる。言語コードは英字・数字・`-`・`_` だけで書く（値は版ディレクトリ名の一部になるため、リポジトリの外へ出る値を防ぐ）。合わない値は、版ディレクトリを見る前に `lang: "<値>" is not a language code. pass --lang with letters, digits, - or _, such as en or ja` で異常終了し、何も変えない。`--lang` を2回以上渡すと、何かを読む前・書く前に `lang: --lang was given more than once. pass it once` で異常終了し、何も変えない

非目標：配布物の生成（`build-rules` が行う）、バイト列をホームへコピーすること、実ファイル・実ディレクトリの削除、リポジトリから配布物を消すこと、翻訳、監視モード、Windows 対応（シンボリックリンクに特権が要る環境は前提にしない）。

実装：Python 3、標準ライブラリのみ、単一ファイル（拡張子なし）。コマンドラインは `install-rules [--home <ホーム>] [--tool <cursor|claude>] [--lang <言語>] [--check]`。対象のリポジトリはスクリプトのあるリポジトリである。`--home` の既定は利用者のホームであり、テストが一時ホームへ配置するために存在する。対象プラットフォームは macOS である。

テスト：テストファーストで、install-skills のテストと同じ流儀（スクリプトを一時的なリポジトリの `scripts/` へコピーし、そこからサブプロセスとして、一時的な `--home` に対して実行する）。ケースは、新規配置で全配布物が両宛先に絶対パスでリンクされ、リンクを読むと配布物のバイトが返ること、2回目の実行で何も変わらないこと、`--check` が配置済み状態で成功し、リンク欠落・リンク先違い・残骸リンク・衝突でパスを名指して失敗し、宛先ディレクトリの欠落ではディレクトリだけを名指すこと、通常実行が残骸リンクを除去しリポジトリ内の配布物は残すこと、リポジトリ移動で壊れたリンクを修復すること、衝突が実行全体を止めてリンクの作成・修復・除去をしないこと、`rules.<lang>` の欠落と配布物の欠落（あるルールのファイルが欠け、兄弟は揃っている場合を含む）で異常終了して何も変わらないこと、ルール名ではない実ファイルが不変であること、および `--tool` のケース（cursor のみと claude のみはその宛先だけにリンクすること、cursor は Claude 側の配布物を要求しないこと、選ばれなかった側の衝突や残骸は実行を止めずそのまま残ること、修復と残骸の除去は選択した宛先だけであること、`--check` は選択した宛先だけを名指すこと、未知の値と繰り返した `--tool` は上の文面で異常終了し何も変えないこと）、および `--lang` のケース（既定では英語版のルール集合を使い、明示した言語ではその版を使い、繰り返した `--lang` は上の文面で異常終了し何も変えないこと）。

完了条件：

1. `--tool` を省いたとき、空のホームに対して、選択した版（既定は `rules.en`）の全ルールが両宛先にリンクされ、全リンクがリポジトリ内のそのルールの配布物へ解決する
2. 2回連続実行で、2回目はリンクの作成・修復・除去を一切しない
3. `--check` が、配置済み状態で正常終了し、リンクの欠落・リンク先違い・残骸・衝突でパスを名指して異常終了し、宛先ディレクトリ自体が無いときだけディレクトリを名指す
4. `rules.<lang>` の欠落、配布物の欠落、または衝突があるとき、異常終了し、何も変えない：リンクの作成・修復・除去を一切せず、配布物も変更しない
5. スクリプトが所有しないエントリ（実ファイル・実ディレクトリ、配布物を指さないリンク）は、失敗した実行を含め、全ての実行の前後で同一である
6. `--tool cursor` または `--tool claude` では、その宛先だけをリンクし、検査し、修復し、掃除し、その宛先の配布物だけを要求する。もう一方の宛先は、失敗した実行を含め、前後で同一である。未知の値、または繰り返した `--tool` は、何も変えない

## translate-rules

目的：ルール版 `rules.<from>/` を `rules.<to>/` へ翻訳する。既定は `--from ja` と `--to en` で、日本語正本から英語版を生成する。どの版が存在し、エージェントがどの版に従うかは別の選択である（翻訳スクリプトは版を生成し、`build-rules` と配置スクリプトは `--lang` で版を選ぶ）。このスクリプトは、指定された言語から指定された言語へ訳すだけである。

入出力の契約：

- 対象は `body.md` と `meta.json` の `description`。`basis.md`（根拠）は承認者が読む文書であり対象外
- 出力は `rules.<to>/<名前>/body.md` と `rules.<to>/<名前>/meta.json` のみ。`rules.<to>/` にはそれ以外を置かない
- `description` を訳す。`cursor` 名前空間は同じ JSON をコピーし、訳さない：`cursor` だけが変わったときは、翻訳器を呼ばずに、新しい `cursor` と前回の訳文の description で `rules.<to>/<名前>/meta.json` を書き直す。既に訳語になっている見出しと識別子はそのまま残す
- 行の契約：訳文は原文の1行につき1行、同じ順序で出す。空行は空行のまま、各行の Markdown の記号（見出しの深さ、リスト記号、表の行、コードフェンス）を保つ。句読点は原文に従い、原文に無い文末のピリオドを足さない。コードフェンスの中の原文も訳す。コメントも訳す。コードのトークンと文字列リテラルは残す。この契約が、前回の訳文を機械的に維持することを可能にする
- 基準は保存した写しではなく git から取る。ルールごとに、基準コミットは `rules.<to>/<名前>/body.md` を最後に変更したコミットである。前回の原文はそのコミット時点の `rules.<from>/<名前>/`、前回の訳文は同じコミット時点の `rules.<to>/<名前>/` であり、作業ツリーではない。そのため対は常に行単位で一致する。前提は、訳したあとに対象の版をコミットすること（レビューもそのとき行う）
- 対象となるのは、現在の原文（`body.md` または `description`）が前回の原文と違うルールと、作業ツリーに `rules.<to>/<名前>/` が無いルール（そのときは全文を訳す）。コマンドラインでルール名を与えると、そのルールに絞る。存在しない名前はエラー
- 原文が変わっていない箇所は、前回の訳文をバイト単位で維持する。前回と現在の原文を行単位で比較し、変わっていない行は前回の訳文の同じ位置の行を使い、変わった行と足された行だけに新しい訳を使う。翻訳器には現在の原文全体と、用語を揃えるために、変わっていない行の前回の訳文だけを [原文, 訳文] の対で渡す。変わった行の古い訳文は見せない：2026-11-23 の実測（既定の組、日本語から英語）で、Haiku はそれを見せると、新しい原文を訳さずに古い行を写した（2回中2回）。レビューは `rules.<to>/` の対象ファイルの差分である
- `rules.<to>/<名前>/` にコミットしていない変更があるルールはエラー（`commit or discard rules.<to>/<name>, then rerun`）。基準の対と一致しない訳文から行を維持すると、位置がずれるため。基準の対で行数が違う場合もエラーで、`rules.<to>/<名前>/` を消すと全文訳の対象になる。黙って全文を訳し直すことはしない
- 翻訳器は Claude Code のコマンド `claude -p` で、モデルは Sonnet。2026-11-23 に下記の JSON の形で実測したところ、Haiku と Sonnet はどちらも18回中18回、行の契約を保った。Sonnet は原文の強調を保ち、文末のピリオドを足さなかった（Haiku は2回足した）。費用は1ルールあたり約1.7円で、Haiku は約0.13円（1ドル＝159円で換算。Claude Code のログインではプランの利用枠から引かれ、円は API で払った場合の相当額）。モデルとプロンプトは `scripts/translator.py` の定数で、translate-skills と共有し、そこが唯一の定義である。認証は、そのマシンに既にある Claude Code のログインである。`--bare` は使わない：`ANTHROPIC_API_KEY` だけを読み、ログインを読まないため
- 翻訳器は隔離して起動する：作業ディレクトリは空の一時ディレクトリとし、`--tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands --no-session-persistence --system-prompt <プロンプト>` を付ける。CLAUDE.md、ルール、フック、MCP サーバー、スキルを読み込まず、翻訳器はファイルに触れる道具を持たない。2026-11-23 の実測：既定の起動は1語の返答でも約32K tokens の文脈を送る。隔離すると約3K
- 1ルールにつき翻訳器の呼び出しは1回。標準入力の依頼と標準出力の答えは、`description` の文字列と、1行につき1要素の `body` 配列を持つ JSON オブジェクトである。2026-11-23 の Haiku での実測：素の行（1行目が description）では、description が `# 見出し` と合体したり入れ替わったりして、行の契約を保ったのは18回中13回だった。この JSON の形では18回中18回保った。呼び出しは1つずつ行い、対象でないルールは一度も呼ばない。2026-11-23 の Sonnet での実測：1ルールあたり平均5.8秒（最大7.3秒）で、うち約3秒がプロセスの起動。何も変わっていない実行は1秒未満
- 次の場合、呼び出しは失敗とする：コマンドが無い、0以外で終了する、タイムアウトを超える（既定120秒、`--timeout <秒>`）、契約を破る出力（空の出力、その形の JSON オブジェクトでない出力、行数や Markdown の記号の違い、原文の文字が残る（既定の組では日本語の文字）、空の description）。失敗した呼び出しは再試行しない。実行は全か無かなので、再実行は安全である
- 全ての対象を訳して検証し終えてから書き込む。どれか1つのルールでも失敗したら、その実行は何も書かず、`rules.<to>/` を実行前のままにする。ファイルは一時ファイルに書いてから置き換えるので、中断しても書きかけのファイルは残らない。エラーはルール名・原因・次のアクション（呼び出しの失敗なら、`claude -p` を成功させてから再実行する）を出す。原文の版は、呼び出しの前に、build-rules と同じく共有の `rule_source.py` で検証する
- 報告は契約の一部である。実行中は、ルールごとに進むたびに1行を出す（`translating <name>`、`copying cursor of <name>`、`unchanged <name>` のいずれか）。複数ルールの実行は1分以上かかるため。最後に、build-rules と同じ形の要約行（`wrote <count> files from rules.<from> under <root>`）と、書いた全ファイルのパスを出す。対象が無い実行は、その旨を出して何も書かない

非目標：Google Translate、DeepL、API キーを要する翻訳器。`rules.<from>/` からルールを消したときの `rules.<to>/<名前>/` の削除（手で行う）。リポジトリを変える git 操作（スクリプトは履歴を読むだけで、コミットはユーザーが行う）。並列呼び出し。ウォッチモード。

実装：Python 3、標準ライブラリのみ、拡張子なしのスクリプトファイル。原文の版の読み込みと検証に共有の `scripts/rule_source.py` を使うことを含め、build-rules と同じ流儀とする。コマンドラインは `translate-rules [--from <言語>] [--to <言語>] [--translator <コマンド>] [--timeout <秒>] [<名前>...]`。対象のリポジトリはスクリプトのあるリポジトリである。`--from` の既定は `ja`、`--to` の既定は `en` で、どちらかを2回以上渡すと、何かを読む前・書く前に `from: --from was given more than once. pass it once` または `to: --to was given more than once. pass it once` で異常終了する。言語コードは英字・数字・`-`・`_` だけで、合わない値は、版ディレクトリを見る前に `from: "<値>" is not a language code. pass --from with letters, digits, - or _, such as en or ja`（`--to` なら `to: "<値>" is not a language code. pass --to with letters, digits, - or _, such as en or ja`）で異常終了する。`--from` と `--to` が同じ言語のときは、同じ版を自分自身へ訳すことになるので、何かを読む前・書く前に `to: --from and --to are both <言語>. pass two different languages` で異常終了する。`--translator` は `claude` コマンドを置き換えるもので、テストで偽の翻訳器を走らせるためにある。偽の翻訳器は同じ引数と標準入力で呼ばれる。Mac と Windows の両方で動くこと：コマンドは `shutil.which` で解決する（`claude.exe` または `claude.cmd`）。標準入出力は UTF-8 を明示する。改行は読み込み時に LF に揃え、LF で書く。タイムアウトした翻訳器は子プロセスごと終了させる。`taskkill` が失敗したとき、または終了させてから10秒たってもプロセスが残るときは、待ち続けずにそのプロセスを名指すエラーにする（`scripts/tests/test_translator.py`）。

テスト：テスト先行で作る。スクリプトは共有モジュールごと一時的な git リポジトリの `scripts/` へコピーし、そこから subprocess として起動し、`--translator` で偽の翻訳器を指す。自動テストは本物の `claude` を呼ばない。ケース：新しいルールを全文訳する。変わった行が置き換わり、変わっていない行は前回の英語をバイト単位で保つ。description だけの変更。`cursor` だけの変更は、翻訳器を呼ばずにコピーする。変わっていないルールは翻訳器を呼ばない。ルール名で絞れ、存在しない名前はエラー。`rules.<to>/<名前>` のコミットしていない変更と、行数が違う基準の対はエラー。git リポジトリでないルートと、`rules.<from>/<名前>` を含まない基準コミットはエラー。変わった行の古い英語は翻訳器に見せない。翻訳器が無い、0以外で終了する、空の出力または JSON でない出力、行数違い、記号の変化、原文の残り、タイムアウト超過は、どれも何も書かない。1つが失敗するルールの混在では、どのルールも書かない。出力の報告（進捗行、要約行の全文、書いた全パス）を検証する。明示した組（`--from en --to fr`）の実行が、その組を訳して `rules.fr/` を作ること。本物の `claude -p` で1ルールを通す手動スモークで、フラグとログインを確かめる。

完了条件：

1. 変わったルールの訳文で、変わっていない原文の行は全て、前回の訳文をバイト単位で保つ
2. `rules.<from>/` に変更が無いとき、翻訳器を一度も呼ばず、何も書かない
3. 呼び出しの失敗または不正な入力では、ルール名・原因・次のアクションを出して異常終了し、`rules.<to>/` は実行前と同一である
4. 翻訳器は CLAUDE.md、ルール、フック、MCP サーバー、スキル、道具のいずれも読み込まずに起動する
5. Mac と Windows の両方で動く

## translate-skills

目的：スキル版 `skills.<from>/` を `skills.<to>/` へ翻訳する。既定は `--from ja` と `--to en` で、日本語正本から英語版を生成する。`install-skills` がどの版をリンクするかは、あちらの `--lang` の選択である。このスクリプトは翻訳だけを行う。

入出力の契約：

- 翻訳器の呼び出しは Markdown 1ファイルにつき1回で、JSON の形、モデル、プロンプト、隔離フラグは translate-rules と同じである（`scripts/translator.py`）。スキル1つを1回にはしない。ファイルをまとめた長い依頼は、実測した行の契約の外である
- `SKILL.md` は `description` と本文を訳す。`name` はディレクトリ名のままで、翻訳器に送らない。他の frontmatter は写す。`basis.md` は版に含めない。Markdown でないファイルはバイト単位で写し、呼び出しはしない
- Markdown のすべての行を送る。コードフェンスの中も送る。そこにある原文も訳す。コメントも訳す。コードのトークンと文字列リテラルは残す。フェンスの記号はフェンスのまま残り、すでに訳先の言語になっている文面はそのまま残る。それは `scripts/translator.py` の行の契約である
- 行の契約、git の基準、変わっていない行を戻す処理は、ファイルごとである。基準は `skills.<to>/<スキル>/<パス>` を最後に変えた commit である。変わっていない行は前回の訳文をバイト単位で保つ。変わった行の古い訳文は送らない。`skills.<to>/<スキル>/` に未コミットの変更があると異常終了し、何も書かない
- 呼び出しは `--jobs` 本同時である（既定4）。最初の行は、1ファイルなら `translating <件数> file, <本数> at a time`、それ以外は `translating <件数> files, <本数> at a time` である。呼び出しの開始は `translating <スキル>/<パス>`、写すファイルは `copying <スキル>/<パス>`、何も要らないファイルは `unchanged <スキル>/<パス>` である。失敗した呼び出しは、走っている呼び出しを止め、新しい呼び出しを始めず、`skills.<to>/` を実行前のままにする。エラーはファイル、原因、次のアクション（`make claude -p succeed, then rerun`）を出す。止められなかったプロセスは、その後に1行ずつ `stop process <pid> by hand` で終わる行として出す
- 全部の呼び出しが成功してから、`wrote <件数> files from skills.<from> under <ルート>` と、書いた全パスを出す。書くものが無い実行は、その旨を出して何も書かない
- `SKILL.md` は、呼び出しの前に `scripts/skill_source.py` で検証する。エラー行は install-skills と同じである

非目標：版のインストール（`install-skills` が行う）、`basis.md` の翻訳、全ファイルを1個の依頼にまとめること、`skills.<from>/` からスキルを消したときの `skills.<to>/<スキル>/` の削除（手で行う）、translate-rules の並列化（あちらは1本ずつを保つ）。

実装：Python 3、標準ライブラリのみ。コマンドラインは `translate-skills [--from <言語>] [--to <言語>] [--translator <コマンド>] [--timeout <秒>] [--jobs <本数>] [<名前>...]`。対象のリポジトリはスクリプトのあるリポジトリである。`--from` の既定は `ja`、`--to` の既定は `en` で、どちらかを2回以上渡すと、何かを読む前・書く前に `from: --from was given more than once. pass it once` または `to: --to was given more than once. pass it once` で異常終了する。言語コードは英字・数字・`-`・`_` だけで、合わない値は、版ディレクトリを見る前に `from: "<値>" is not a language code. pass --from with letters, digits, - or _, such as en or ja`（`--to` なら `to: "<値>" is not a language code. pass --to with letters, digits, - or _, such as en or ja`）で異常終了する。`--from` と `--to` が同じ言語のときは、同じ版を自分自身へ訳すことになるので、何かを読む前・書く前に `to: --from and --to are both <言語>. pass two different languages` で異常終了する。`--jobs` が1未満のときは `jobs: --jobs must be at least 1. pass --jobs 4` で異常終了し、何も変えない。

テスト：スクリプトを共有モジュールごと一時的な git リポジトリの `scripts/` へコピーし、そこから subprocess として起動する。`--translator` の偽翻訳器を使う。本物の `claude` は呼ばない。ケース：新しい `SKILL.md` は `name` を保ち、`description` と本文を訳す。フェンスの中は依頼にあり、出力では訳されている。`basis.md` は出さず、シェルスクリプトは写す。変わっていないスキルは呼び出さない。訳すファイルがあるとき、件数の行は `unchanged` と `copying` の行より先に出る。変わった行は新しい英語になり、その行の古い英語はプロンプトに無い。`--jobs 2` では2つの呼び出しが重なり、失敗した呼び出しは何も書かない。`--jobs 0` と `SKILL.md` の欠落は呼び出しをしない。明示した `--from en --to fr` の実行が、`skills.en/` から `skills.fr/` を作る。

書くのは「なぜ」と「契約」。振る舞いの細部はテストが、実装方法はコードが正本である。
