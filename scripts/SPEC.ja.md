# scripts ディレクトリ仕様（SPEC）

この SPEC は scripts ディレクトリの仕様書である。

ルールとスキルの言語版を処理するスクリプトを置く。正本は `rules.ja/` と `skills.ja/` で、他の版（例えば `rules.en/` と `skills.en/`）は翻訳スクリプトが正本から生成する。`build-rules`、`install-rules`、`install-skills`、`translate-rules`、`translate-skills` は実装済み。

| スクリプト | 仕事 |
|---|---|
| `build-rules` | `--lang` で選んだルール版から配布物（Cursor 版／Claude 版）を決定的に生成する |
| `install-skills` | `--lang` で選んだ版のスキルを、ホームのスキル置き場へシンボリックリンクとして配置する |
| `install-rules` | `build-rules` が書いた配布物を、ホームのルール置き場へシンボリックリンクとして配置する |
| `translate-rules` | ルール版 `rules.<from>/` を `rules.<to>/` へ翻訳する（既定は正本から英語版） |
| `translate-skills` | スキル版 `skills.<from>/` を `skills.<to>/` へ翻訳する（既定は正本から英語版） |

全スクリプト共通（以降の節では繰り返さない）：

- 各スクリプトは拡張子なしの Python 3 標準ライブラリのみのファイルで、自分を含むリポジトリに対して働く。build-rules と翻訳スクリプトは Mac と Windows で動く。配置スクリプトはシンボリックリンクを使うので macOS のみ
- `--lang <言語>`（build-rules、install-*。既定 `en`）は `rules.<言語>/` または `skills.<言語>/` の版を選ぶ。翻訳スクリプトでは `--from`（既定 `ja`）と `--to`（既定 `en`）が同じ役を担い、2つは別の言語でなければならない。版のディレクトリが存在する言語なら何でも使える。言語コードは英数字、`-`、`_` のみで、リポジトリの外へ出る値は通らない。不正なコード、オプションの重複指定、`--from` と `--to` が同じ言語、はどれも何かを読み書きする前にエラーにする
- `--tool <cursor|claude>`（install-*）は実行を片方の配置先（`<home>/.cursor/...` か `<home>/.claude/...`）に絞る。省略すると両方。選ばれなかった側は作らず、読まず、報告せず、そこにある衝突・古いリンク・欠けた配布物は実行に影響しない。未知の値と重複指定は、何も変更する前にエラーにする
- `--check`（build-rules、install-*）は何も書かず、ずれを報告する。`--home`（install-*）と `--translator`（translate-*）は、テストが一時ホームと偽の翻訳コマンドを使えるようにするためにある
- エラーは対象の単位（ルール、スキル、ファイル）、原因、次の行動を示し、終了コードで成否を伝える。失敗した実行は何も書かず、作らず、直さず、消さない。最初の変更の前に入力をすべて検証する。文言の厳密な形はテストが固定する
- 報告は契約の一部である。通常の実行は要約行と、書いた／リンクした全パスを出す。成功した `--check` は何を確認したかと、何も書かなかったことを出す。成功が無言なのは欠陥である（何も起きなかったのと区別できない）。失敗した `--check` は、問題を操作者が動く単位（`differs`、`missing`、`stale`、`conflict`）で名指しする。ディレクトリごと欠けている、または空のときは、そのディレクトリを1回だけ名指しする
- 自分の出力に対して再実行しても何も変わらない（冪等）
- ルールの生成と配置は、同じ `--lang` で続けて行う。配布物は、どの言語から作ったかを記録しないため
- 振る舞いの細部（エラー文面、報告形式、ケース）の正本は `scripts/tests/` のテスト。テストは一時リポジトリの中で各スクリプトをサブプロセスとして実行する。自動テストは本物の `claude` を呼ばない

## build-rules

目的：`rules.<lang>/<名前>/` の `body.md` と `meta.json` から、`.cursor/rules/<名前>.mdc` と `.claude/rules/<名前>.md` を生成する。`<lang>` は `--lang` で選ぶ言語である。

入出力の契約：

- 入力は選んだ版だけ。出力は入力の純関数で、同じ入力は常に同じバイト列になる
- 生成物に印のヘッダは付けない。正本とのずれは、ファイル内の文字ではなく `--check` で検出する
- 欠けたファイル、異なるファイルは個別に名指しする。存在して何かが入っているディレクトリ（無関係なファイルだけでも）は空ではない。その場合は欠けている配布物を1つずつ名指しする

非目標：翻訳、ホームへの配置、git 操作、監視モード、差分処理。

変換表（正本の `meta.json` は、トップレベルの `description` と `cursor` 名前空間を持つ）：

| meta.json | Cursor 版（.mdc） | Claude 版（.md） |
|---|---|---|
| `cursor.alwaysApply: true` | frontmatter に `alwaysApply: true` | frontmatter なし |
| `cursor.globs` あり | frontmatter に `globs` | frontmatter に `paths` として出す |
| それ以外（description のみ） | frontmatter に description のみ | frontmatter なし |

frontmatter の値は引用符なしの素のスカラーで、キーの順は description、globs、alwaysApply。

注：Claude Code のルール読み込みは frontmatter の `paths` だけを見る。`alwaysApply` は読まない。`~/.claude/rules/` に置いたファイルは常駐で読まれる。自動ルール（description のみ）をホーム側でどう扱うかは、配置設計の未決事項（実測で確認待ち）。

検証：

- 先にすべてのルールを `scripts/rule_source.py`（translate-rules と共有。ルールは両方で有効か、両方で無効かのどちらか）で検証する。`meta.json` は、文字列の `description` とオブジェクトの `cursor` を持つオブジェクトでなければならない。トップレベルと `cursor` 内の未知のキーは拒否する。`cursor.globs` は、ある場合は文字列か null（null は globs なし）。`cursor.alwaysApply` は、ある場合は真偽値。`body.md` が存在すること。`rules.<lang>` が無ければエラー

完了条件：

1. 実ルールの凍結スナップショット（`scripts/tests/fixtures/real/`。日本語の正本を持つ）に対して、生成物が期待出力とバイト単位で一致する
2. 続けて2回実行しても、2回目の差分はゼロ
3. `--check` は、出力が選んだ版と一致すれば正常終了し、生成物が手で編集された、ファイルが欠けた、出力ディレクトリが無いか空である、のいずれかではエラーで終了する。ずれたファイルを名指しし、ディレクトリ自体が無い／空のときはディレクトリだけを名指しする。無関係なファイルが残るディレクトリはこの場合に当たらず、欠けている配布物を1つずつ名指しする
4. 不正な入力ではエラーで終了し、出力ファイルを一切書かない
5. globs を持つ fixture で、Claude 版が正しい `paths` の frontmatter を持つ

## install-skills

目的：`skills.<lang>/<名前>/` のスキルを、ホームのスキル置き場（`~/.claude/skills/` と `~/.cursor/skills/`）へ、スキル1つにつきシンボリックリンク1本として配置する。リンクの先はこのリポジトリのスキルディレクトリ。スキルには形式変換が要らないので、配置はコピーではなくリンクで行う。リポジトリの版だけが実体で、スキルを編集すれば再配置なしで反映される。

入出力の契約：

- 配置の単位はスキルのディレクトリ。リンクは中身すべてを覆う。再配置が要るのは、スキルを丸ごと足す・消すときだけ
- リンク先はリポジトリ配下の絶対パス。リポジトリを動かすとリンクは壊れる。`--check` が報告し、通常の実行が直す
- スクリプトが管理するのは、このリポジトリのスキル版（任意の言語の `skills.<lang>/`）の中を指すシンボリックリンクだけ。実ファイルや実ディレクトリを作らず、上書きせず、消さない。他が指すリンクにも触れない。他者が持つエントリ（例：Claude Code がユーザーの claude.ai アカウントから取得したスキルを置く `~/.claude/skills/synced/`）は管理の外
- 選んだ版とは別の、このリポジトリの版を指すリンクは誤ったリンク先である。通常の実行は直し、`--check` は `differs` と報告する
- スキルの邪魔をする配置先のエントリ（実ファイル／実ディレクトリ、またはリポジトリの外を指すリンク）は衝突である。衝突は何かを変更する前に検出する
- 選んだ配置先にあり、このリポジトリのスキル版を指すが、選んだ版に存在しないスキルのリンクは古い（stale）。通常の実行は消し、`--check` は報告する。消すのは、このリポジトリを指すリンクだけ

非目標：スキルファイルのコピー、ルールの配置（`install-rules` がリンクする）、実ファイルや実ディレクトリの削除、プラグインのスキルや claude.ai 同期スキルの管理、監視モード、Windows 対応。

検証：

- `skills.<lang>` が存在すること。その直下のサブディレクトリはすべてスキルで、`SKILL.md` を持たなければならない。frontmatter は単純な `key: value` の行として読み（YAML ライブラリは使わない）、ディレクトリ名と等しい空でない `name` と、空でない `description` を持つこと。コロンのない空でない frontmatter 行、閉じの `---` がない frontmatter、同じキーの2回指定は、読み飛ばしや上書きではなくエラー。その他の frontmatter キーは許す。`synced` というスキル（大文字小文字を問わない）は、`claude` が選ばれた配置先のときは拒否する。Claude Code が `~/.claude/skills/` 下でその名を予約しているため。`--tool cursor` だけのときは普通のスキル

完了条件：

1. 空のホームへ、`--tool` なしで実行すると、選んだ版（既定 `skills.en`）のすべてのスキルが両方の配置先にリンクされ、各リンクはリポジトリ内のそのスキルのディレクトリに解決する
2. 続けて2回実行しても、2回目は何も作らず、直さず、消さない
3. `--check` は配置済みの状態で正常終了し、リンクの欠け、誤ったリンク先、古いリンク、邪魔をするエントリの衝突ではパスを名指ししてエラーで終了し、配置先ディレクトリ自体が無いときはディレクトリだけを名指しする
4. 不正な入力や衝突があればエラーで終了し、何も変更しない。リンクの作成、修復、削除はない
5. スクリプトが所有しないエントリ（実ファイルと実ディレクトリ、このリポジトリの外を指すリンク、`synced/`）は、失敗した実行も含め、どの実行の前後でも同一
6. `--tool cursor` または `--tool claude` では、その配置先だけをリンク、確認、修復、掃除する。もう一方は、失敗した実行も含め前後で同一。未知の `--tool` や重複した `--tool` は何も変更しない

## install-rules

目的：`build-rules` が書いた配布物（`.cursor/rules/<名前>.mdc` と `.claude/rules/<名前>.md`）を、ホームのルール置き場（`~/.cursor/rules/` と `~/.claude/rules/`）へ、ファイル1つにつきシンボリックリンク1本として配置する。配置は配布物を生成もコピーもしない。配布物はリポジトリの `.cursor/` と `.claude/` の下に残る。

入出力の契約：

- ルールの集合は `rules.<lang>/` のサブディレクトリ。選んだ各配置先に、そのルールの配布物が既に存在していなければならない。無ければ `build-rules` を実行するよう促すエラーで、何も変更しない。配布物ファイル自体は変更しない
- リンク先はリポジトリ配下の絶対パス。リポジトリを動かすとリンクは壊れる。`--check` が報告し、通常の実行が直す
- スクリプトが管理するのは、`.cursor/rules/` か `.claude/rules/` の配布物を指すシンボリックリンクだけ。実ファイルや実ディレクトリを作らず、上書きせず、消さない。他を指すリンクにも触れない
- ルールファイルの邪魔をする配置先のエントリ（実ファイル／実ディレクトリ、または配布物を指さないリンク）は衝突である。衝突は何かを変更する前に検出する
- 選んだ配置先にあり、もう `rules.<lang>/` に無いルールの配布物を指すリンクは古い（stale）。通常の実行は消し、`--check` は報告する。消すのはそのようなリンクだけで、リポジトリの配布物は残す

非目標：配布物の生成（`build-rules` が行う）、ホームへのバイト列のコピー、実ファイルや実ディレクトリの削除、リポジトリの配布物の削除、翻訳、監視モード、Windows 対応。

完了条件：

1. 空のホームへ、`--tool` なしで実行すると、選んだ版（既定 `rules.en`）のすべてのルールが両方の配置先にリンクされ、各リンクはリポジトリ内のそのルールの配布物に解決する
2. 続けて2回実行しても、2回目は何も作らず、直さず、消さない
3. `--check` は配置済みの状態で正常終了し、リンクの欠け、誤った配布物を指すリンク、古いリンク、邪魔をするエントリの衝突ではパスを名指ししてエラーで終了し、配置先ディレクトリ自体が無いときはディレクトリだけを名指しする
4. `rules.<lang>` の欠け、配布物の欠け、衝突があればエラーで終了し、何も変更しない。リンクの作成、修復、削除はなく、配布物も変更しない
5. スクリプトが所有しないエントリ（実ファイルと実ディレクトリ、配布物を指さないリンク）は、失敗した実行も含め、どの実行の前後でも同一
6. `--tool cursor` または `--tool claude` では、その配置先だけをリンク、確認、修復、掃除し、その配置先の配布物だけが必要。もう一方は、失敗した実行も含め前後で同一。未知の `--tool` や重複した `--tool` は何も変更しない

## translate-rules

目的：ルール版 `rules.<from>/` を `rules.<to>/` へ翻訳する。既定は `--from ja`、`--to en`：日本語の正本から英語版へ。どの版が存在するかと、エージェントがどれに従うかは別の選択である（`build-rules` と配置スクリプトが `--lang` で選ぶ）。このスクリプトは翻訳だけを行う。

入出力の契約：

- 対象は `body.md` と `meta.json` の `description`。`basis.md`（根拠）は承認者向けの文書で、対象外
- 出力は `rules.<to>/<名前>/body.md` と `rules.<to>/<名前>/meta.json` のみ
- `description` は翻訳する。`cursor` 名前空間は同じ JSON のままコピーし、翻訳しない。`cursor` だけが変わったときは、翻訳コマンドを呼ばずに、新しい `cursor` と前回の訳文の description で `meta.json` を書き直す。すでに訳文の言語になっている見出しや識別子はそのまま残す
- 行の契約：訳文は、原文の1行につきちょうど1行を、同じ順序で持つ。空行は空行のまま、各行は Markdown の記号（見出しレベル、リストマーカー、表の行、コードフェンス）を保つ。句読点は原文に従い、原文に末尾の句点がなければ足さない。コードフェンス内の原文言語のテキスト（コメントを含む）は翻訳し、コードのトークンと文字列リテラルは残す。この契約があるから、前回の訳文を残す処理が機械的にできる
- 基準は保存したコピーではなく git から取る。ルールごとに、基準コミットは `rules.<to>/<名前>/body.md` を最後に変えたコミット。前回の原文はそのコミットの `rules.<from>/<名前>/`、前回の訳文は同じコミットの `rules.<to>/<名前>/`（作業ツリーではない）で、対が常に行単位で一致する。訳した版は、訳した後にコミットされている必要がある。レビューもそのときに行う
- ルールが対象になるのは、現在の原文（`body.md` または `description`）が前回の原文と異なるとき、または `rules.<to>/<名前>/` が存在しないとき（その場合は全文を翻訳する）。コマンドラインのルール名は、実行をそのルールに絞る。未知の名前はエラー
- 原文が変わっていない箇所は、前回の訳文をバイト単位で保つ。変わっていない各行は同じ位置の前回の訳文の行を取り、変更・追加された行だけが新しい翻訳を取る。翻訳コマンドには、現在の原文全体と、用語を揃えるために、変わっていない行の前回の訳文だけを [原文, 訳文] の対として渡す。変更された行の古い訳文は決して見せない。見せると、モデルが新しい原文を訳さず古い行をそのまま写すため
- `rules.<to>/<名前>/` に未コミットの変更があるルールはエラー（コミットか破棄して再実行）。基準の対の行数が食い違う場合もエラー。`rules.<to>/<名前>/` を消せば、そのルールは全文翻訳になる。黙って全文を再翻訳することはしない
- 翻訳器は Claude Code のコマンド `claude -p`（Sonnet モデル）で、マシンにすでにあるログインを使う（`--bare` は使わない。`ANTHROPIC_API_KEY` しか読まず、ログインを読まない）。モデルとプロンプトは `scripts/translator.py` の定数で、translate-skills と共有する。このモジュールが唯一の定義
- 翻訳器は隔離して動かす。作業ディレクトリは空の一時ディレクトリで、`--tools "" --strict-mcp-config --setting-sources "" --disable-slash-commands --no-session-persistence --system-prompt <prompt>` で起動する。CLAUDE.md、ルール、フック、MCP サーバー、スキルは読み込まれず、ファイルに触れるツールも持たない
- ルール1つが翻訳コマンド1回の呼び出しで、呼び出しは1つずつ順に行う。標準入力のリクエストと標準出力の回答は、文字列の `description` と、1行につき1文字列の配列 `body` を持つ JSON オブジェクト（素の行だと、モデルが description をタイトル見出しに混ぜてしまう）。対象でないルールは呼び出さない
- 呼び出しが失敗とされるのは、コマンドが無い、非ゼロで終了する、タイムアウト（既定120秒、`--timeout <秒>`）を超える、または出力が契約を破るとき：出力が空、その形の JSON オブジェクトではない、行数や Markdown の記号が違う、原文言語の文字が残っている、description が空。失敗した呼び出しは再試行しない。実行は全部か無かなので、再実行しても安全。タイムアウトした翻訳器は子プロセスごと止める。止められなければ、エラーがそのプロセスを名指しする
- 書き込みの前に、すべての対象を翻訳して検証する。どれか1つでも失敗したら `rules.<to>/` は元のまま。ファイルは一時ファイルを経由して置き換えるので、中断した実行が書きかけのファイルを残さない。原文の版は、呼び出しの前に共有の `rule_source.py` で検証する
- 進捗は進むごとに、ルール1つにつき1行（翻訳中、`cursor` のコピー、変更なし）出す。数ルールの実行は1分以上かかるため。対象のない実行は、その旨を言って何も書かない

非目標：Google 翻訳、DeepL、API キーを必要とする翻訳器すべて、`rules.<from>/` からルールが消えたときの `rules.<to>/<名前>/` の削除（手で行う）、リポジトリを変更する git 操作（履歴を読むだけで、コミットは利用者が行う）、並列呼び出し、監視モード。

完了条件：

1. 変更されたルールは、変わっていない原文の各行が前回の訳文をバイト単位で保った訳文を生む
2. `rules.<from>/` に変更がなければ、実行は翻訳コマンドを呼ばず、何も書かない
3. 失敗した呼び出しや不正な入力では、ルール名、原因、次の行動を示すエラーで終了し、`rules.<to>/` は前後で同一
4. 翻訳器は CLAUDE.md、ルール、フック、MCP サーバー、スキル、ツールなしで起動する
5. Mac と Windows の両方で動く

## translate-skills

目的：スキル版 `skills.<from>/` を `skills.<to>/` へ翻訳する。既定は `--from ja`、`--to en`：日本語の正本から英語版へ。`install-skills` がどの版をリンクするかは、そのスクリプト自身の `--lang` の選択で、このスクリプトは翻訳だけを行う。

入出力の契約：

- 翻訳コマンドの1回の呼び出しは Markdown ファイル1つ。JSON の形、モデル、プロンプト、隔離フラグは translate-rules と同じ（`scripts/translator.py`）。スキル全体で1回ではない。長くまとめたリクエストは行の契約の範囲外
- `SKILL.md` は `description` と本文を翻訳する。`name` はディレクトリ名のままで、送らない。他の frontmatter キーはコピーする。`basis.md` は版に含めない。Markdown でないファイルはバイト単位でコピーし、呼び出さない
- Markdown ファイルのすべての行を送る。コードフェンス内の行も含む。そこにある原文言語のテキストはコメントを含め翻訳し、コードのトークンと文字列リテラルは残す。フェンスの記号はフェンスの記号のまま。すでに訳文の言語であるテキストは残す（`scripts/translator.py` の行の契約）
- 行の契約、git の基準、つなぎ合わせはファイル単位。基準は `skills.<to>/<スキル>/<パス>` を最後に変えたコミット。変わっていない行は前回の訳文をバイト単位で保つ。変更された行の古い訳文は送らない。`skills.<to>/<スキル>/` に未コミットの変更があればエラーで、何も書かない
- 呼び出しは `--jobs` 個ずつ並行して行う（既定4。1未満はエラー）。最初の行がファイル数と並行数を示し、続けてファイルごとに1行（翻訳中、コピー、変更なし）。失敗した呼び出しは、実行中の呼び出しを止め、新しい呼び出しを始めず、`skills.<to>/` を変えない。止められなかったプロセスは、独立した1行で、次の行動（手で止める）とともに名指しする
- `SKILL.md` は、呼び出しの前に `scripts/skill_source.py`（install-skills と同じ行）で検証する

非目標：版の配置（`install-skills` が行う）、`basis.md` の翻訳、全ファイルを1つにまとめたリクエスト、`skills.<from>/` からスキルが消えたときの `skills.<to>/<スキル>/` の削除（手で行う）、translate-rules での並列呼び出し（そのコマンドは1つずつのまま）。

## この仕様書の持ち方

書くのは「なぜ」と「契約」。振る舞いの細部はテストが、実装方法はコードが正本である。
