# Claude Dispatch

`claude -p` で Claude Code に作業をワンショットで派遣するときの手順。派遣先のセッションは「今いるブランチ専用」と決まっていて、どの入り口から派遣しても同じセッションに集まる。実行は対象リポジトリのチェックアウトの中で行う。

## 前提

- セッションのトランスクリプトは `cleanupPeriodDays`（settings.json、既定30日）で消える。ブランチセッションを30日を超えて維持するなら、設定で引き上げておく（例：365）

## 手順

1. 現在のブランチを取る：`git branch --show-current`。空なら detached HEAD なので、派遣せずにその旨を報告して止まる
2. ブランチがデフォルトブランチ（main）の場合：対応表は使わず、`claude -p "<タスク>" --no-session-persistence` で使い捨ての新規セッションとして実行する。記録も resume もしない。手順はここで終わり
3. 対応表を読む：`git rev-parse --path-format=absolute --git-common-dir` で git ディレクトリの絶対パスを取り、その中の `claude-sessions.json` を読む（無ければ空の表として扱う）。対応表は JSON で、キーがブランチ名、値がセッション ID と作成したチェックアウトの絶対パス（cwd）の組
4. ブランチのエントリがある場合：記録された cwd が今のチェックアウトと違えば、そちらに移動してから `claude -p "<タスク>" --resume <セッション ID>` で実行する（セッションはディレクトリに紐付く）
5. resume が「No conversation found」で失敗した場合、または記録された cwd が既に無い場合：セッションが消えたものとして扱う。手順6の新規作成で作り直して対応表を更新し、タスクを再実行する。この復旧は1回だけ試し、前の文脈が失われたことを報告に含める
6. エントリが無い場合：`uuidgen` で UUID を発行し、`claude -n <ブランチ名> --session-id <UUID> -p "<タスク>"` で実行する。成功したら対応表にブランチ名、ID、今の cwd を記録する。失敗したら記録しない
7. 結果を受け取り、要約してユーザーに報告する

対応表への書き込みは、一時ファイルに書いてから rename して原子的に差し替える。

## タスク文の書き方

- セッションにはブランチ作業の文脈があるが、タスク文はそれに頼らず自己完結に書く（依頼内容、対象、完了条件を含める）
- 返ってくるのは最終テキストだけなので、報告に必要な情報（変更したファイル、テスト結果など）はタスク文の中で求めておく

## 守ること

- `--continue` は使わない。継ぐ先は常に対応表のブランチセッションにする
- `--dangerously-skip-permissions` は使わない。権限で止まった操作は失敗として報告する
- 起動フラグ（権限モード、`--mcp-config`、`--settings`、許可リストなど）は resume で復元されない。派遣の条件として必要なものは、作成時・resume 時を問わず毎回コマンドに付ける
- ユーザーが「新規セッションで」と明示したときだけ、新しい UUID で作り直して対応表を差し替える
- 対話側（ターミナルやパネル）で続きをやるときも、同じブランチセッションを名前（ブランチ名）で resume する

## Decision test

- 派遣先が「今いるブランチ専用のセッション」（main の場合は使い捨て）と機械的に言えるか。対応表に無い、detached、名前が違う、記録と違うチェックアウトから resume している、main なのに継続セッションへ集めている、のどれかの状態で実行していないか
