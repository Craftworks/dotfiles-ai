# 仕様からテストへの移植

仕様文書に書かれたテスト仕様を、テストコードへ移す手順。
発火の条件は、change-discipline の Done means（仕様の圧縮）に従う。
このファイルは手順だけを持ち、判定基準は change-discipline にある。

## 移すもの

振る舞いの細部。

- 入出力のケースの列挙
- 正確なエラー文面
- 報告・出力の形式
- 境界値と、その期待結果

## 移さないもの

次はテストコードでは表せない。文書に残す。

- なぜと契約、非目標
- 完了条件（受け入れ水準そのもの）
- 意図的にテストしない範囲
- オラクルの独立性の条件（何を正解とするか。例：凍結したサンプルが正解であり、実装の出力から期待値を作らない）

テストコードは、「書かれていないこと」と「期待値が実装から独立していること」を表せない。

## 手順

1. 文書の記述をオラクルにして、対応するテストを書く／強くする。期待値は文書から取る
2. 項目ごとに、change-discipline の削除判定を適用する。判定を通らない項目は移さない。文書に残すか、先にテストを強くする
3. テストが固定した項目だけを、文書から消す
4. スイート全体を回す
5. 完了報告に、移した項目と、文書に残した項目を添える

## 失敗モード

- 実装の現在の出力を期待値として移す。テストが実装に従属し、仕様としての独立性を失う
- 項目ごとに照合せず、まとめて消す。テストが固定していない細部が、文書からもテストからも消える
