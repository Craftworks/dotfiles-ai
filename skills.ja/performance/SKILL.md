# Performance

最適化は計測から始める。推測で書き換えず、実測されたボトルネックだけを、決まった順序で直す。

## 手順

1. **計測してボトルネックを特定する**：計測・プロファイラ・ログ・簡易ベンチで、遅さの所在を特定してから着手する
2. **まず無駄を潰す**：N+1、重複フェッチ、不要な再レンダー／再計算を先に除去する
3. **ホットパスを短く保つ**：割り当て・コピー・ロック・同期 I/O を意識し、頻繁に通る経路へ重い処理を持ち込まない
4. **キャッシュは設計とセットで入れる**：無効化条件と寿命を必ずセットで決める。キー設計のないメモ化は入れない
5. **複雑度を変更理由に含める**：時間・空間・往復回数への影響を、変更の理由として明記する

## 判断の順序

迷ったら、この順序を守る：

1. 正しさ
2. 明瞭さ
3. 実測されたボトルネックの除去
4. 必要ならアルゴリズム／データ構造の変更

## 反パターン

- 計測なしの「速そう」リライト
- 読みにくさを増やすだけの微最適化
- 全体を非同期／並列にするだけで直した気になる
- 無制限キャッシュ、またはキー設計のないメモ化

## 出口条件

次を満たしたら完了とする：

- ボトルネックが計測で特定されている（推測で着手していない）
- 変更の効果が、変更前後の実測で示せる
- 複雑度（時間・空間・往復回数）への影響が変更理由に含まれている
