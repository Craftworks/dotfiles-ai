# Operator UX

使う人がオペレータ（起動・監視・停止する人）であるとき、その体験は目的側の上位要件である。ログファイルに逃して沈黙させない。

画面プロダクトの見た目は `ui-ux` スキルを参照する。こちらは**制御面と運行の分かりやすさ**を扱う。

## 手順

1. **状態を一目で分かるようにする**：今の状態（起動中／停止／待機／エラー／権限不足）と、今なにをしているか（どのロールが、何を待っている／送っているか）が言える表示にする
2. **進捗と待機を区別する**：待機には理由と経過を示し、進捗のない状態（詰まり）を正常な待機と区別できるようにする。フォアグラウンド実行（CLI・バッチ等を端末で人が見ている実行）では、各ステップの開始・完了・経過をリアルタイムに表示し、長時間の無出力で人間を待たせない。すぐ終わるコマンドも、完了時に何をしたか（件数、対象、書き込んだか検査だけか）を出す。無出力の成功は、何も起きなかったことと区別できない
3. **停止理由を残す**：なぜ止まったか（権限、心拍途切れ、契約違反、未知入力、など）を、オペレータがその場で読める形で残す
4. **起動・停止・再起動の経路を一本化する**：二重起動や片肺運転を防ぐ。停止は一手で全ロールに伝わり、停止完了が状態表示で確認できるようにする
5. **成功を証拠で示す**：成功は「送った」や終了コードだけで済ませない。オペレータが追える証拠（次状態、対象の一覧、ログ、ヘルス）で示す

## 反パターン

- 起動した端末やプロセスが存在することだけを、ステータス表示の代わりにする（例：Terminal が複数開いているだけ）
- 失敗を無言終了や散在ログだけにする
- 片方のプロセスだけ残る運用を許容する（古い判定で動き続ける、など）
- デバッグ用の生出力を、そのまま唯一の UX にする
- 同じ原因を、子要素ごとに繰り返して唯一の表示にしない。オペレータが操作する単位（ディレクトリが無い、ディレクトリが空）で一度出す

## 出口条件

次を満たしたら完了とする：

- Decision test：**知らない人が60秒で「動いているか／止めるか／何が悪いか」を判断できるか**
