# スキルの機構

[`writing-for-agents`](SKILL.md) のスキル固有の分岐：文書がスキルのときに変わること（frontmatter、呼び出し方式の選択、ルータースキル）。それ以外の書き方のすべては、`SKILL.md` の普遍的な参照に従う。

## 呼び出し方式

2つの選択肢は、2つの負荷の交換である：

- **model-invoked（モデル呼び出し）** なスキルは `description` を持ち、エージェントが自律的に発火でき、他のスキルからも到達できる。人間が名前を打つことも引き続きできる：モデル呼び出しは人間の到達を常時含み、description はエージェントの発見を足すだけで、人間の到達を取り除くことは決してない。description はスキルの最上位の context pointer であり、常時読み込まれ続けることを強いられる：発見可能性と引き換えの、恒常的なコンテキスト負荷である。内容が全部参照である model-invoked スキルは、共有参照の置き場の1つでもある：別のスキルがそれを呼び出せるので、複数のスキルが必要とする参照が1か所に住める。機構：`disable-model-invocation` を付けず、発火の分岐を持つモデル向けの description を書く（`SKILL.md` のポインタの書き方の規則が全面的に適用される）
- **user-invoked（ユーザー呼び出し）** なスキルは、エージェントの到達範囲から description を取り除く：名前を打つ人間だけが呼び出せ、他のスキルは呼び出せない。コンテキスト負荷はゼロだが、認知負荷を使う：存在を覚えている索引は人間である。機構：`disable-model-invocation: true` を付け、description は人間向けにする：1行の要約で、トリガーの列挙は取り除く

モデル呼び出しを選ぶのは、エージェントが自力でそのスキルに到達しなければならないとき、または他のスキルが到達しなければならないときだけ。それ以外は手で発火させるだけなら、ユーザー呼び出しにしてコンテキスト負荷を払わない。

2つの user-invoked スキルが両方必要とする共有参照は、どちらの中にも住めない：description が無いので、互いを発火できない。スキル機構の外の素のファイルへ押し出す：どのスキルからでも指せる外部参照である。

## 呼び出し方式で分割する

分割の呼び出し方式の切り口（順序の切り口は `SKILL.md` にある）：独立した leading word を持ち、それ自体で発火すべきものがあるとき、または他のスキルが到達しなければならないときに、model-invoked スキルを切り分ける。新しい常時読み込みの description の分だけコンテキスト負荷を払うので、その独立した到達にはそれだけの価値が要る。

## ルータースキル

user-invoked スキルが、人間が覚えていられる数を超えて増えたら、その積み上がった認知負荷を治すのが**ルータースキル**である：他のスキルを名指しし、それぞれにいつ手を伸ばすかを示す user-invoked スキルが1つあれば、人間が覚えるスキルは1つで済む。ルーターは示唆できるだけで、発火はできない：user-invoked スキルには description が無いので、人間以外に到達する手段が無い。
