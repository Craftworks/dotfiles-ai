# scripts ディレクトリ仕様

この README は scripts ディレクトリの仕様書である。

`rules.ja/` と `skills.ja/` の正本を処理するスクリプトを置く。`build-rules` と `build-skills` は実装済み。`translate-rules` は未実装（設計のみ）。

| スクリプト | 仕事 |
|---|---|
| `build-rules` | 正本から配布物（Cursor 版／Claude 版）を決定的に生成する |
| `build-skills` | 正本のスキルを、ホームのスキル置き場へシンボリックリンクとして配置する |
| `translate-rules` | 正本から公開用英語版 `rules.en/` を生成する |

## build-rules

目的：`rules.ja/<名前>/` の `body.md` と `meta.json` から、`.cursor/rules/<名前>.mdc` と `.claude/rules/<名前>.md` を生成する。

入出力の契約：

- 入力は正本のみ。出力は入力の純粋な関数であり、同じ入力からは常に同じバイト列が出る（冪等）
- 生成物には目印のヘッダを付けない。正本とのズレはファイル内の文言ではなく `--check` で検出する
- `--check` は書き込まず、生成物と正本の一致だけを検査し、ズレたファイル名を示して異常終了する
- 報告も契約の一部である。通常実行は、何をしたかを標準出力に出す：要約行（`wrote <件数> files from rules.ja under <ルート>`）に続けて、書き込んだ全ファイルのパスを出す。`--check` の成功時は `checked <件数> files from rules.ja under <ルート>; all match; wrote nothing` に続けて、検査した全パスを出す。無言の成功は欠陥である：何も起きなかったことと区別できない
- `--check` の失敗時は、標準エラーに要約行、問題ごとの行、次のアクション（`run without --check to write them.`）を出す。ズレたファイルと欠けたファイルは個別に名前を出す（`differs: <パス>`、`missing: <パス>`）。出力ディレクトリ自体が無い・空の場合は、配下のファイルを列挙せず、ディレクトリを一度だけ名指す（`missing: <ディレクトリ>`、`empty: <ディレクトリ>`）。空とは、ディレクトリにエントリが1つも無いことである。ディレクトリが存在し、無関係なファイルを含め何かが入っている場合は空ではなく、欠けた生成物をそれぞれ `missing: <パス>` で名指す。問題は、オペレータが操作する単位で報告する

非目標：翻訳、ホームへの配置、git 操作、監視モード、増分処理。

変換表（正本の `meta.json` は `description` と `cursor` 名前空間を持つ）：

| meta.json | Cursor 版（.mdc） | Claude 版（.md） |
|---|---|---|
| `cursor.alwaysApply: true` | frontmatterに `alwaysApply: true` | frontmatterなし |
| `cursor.globs` あり | frontmatterに `globs` | frontmatterに `paths` として出力 |
| それ以外（description のみ） | frontmatterに description のみ | frontmatterなし |

注：Claude Code のルール読み込みはfrontmatterの `paths` のみを見て、`alwaysApply` は読まない。`~/.claude/rules/` に置かれたファイルは常駐ロードされる。auto（description のみ）のルールをホーム側でどう扱うかは install 設計の未決事項（実測による確認待ち）。

検証とエラー：

- 全ルールの検証を終えてから書き始める。`meta.json` は object であり、`description` は文字列、`cursor` は object である。未知キーはトップレベルと `cursor` の中の両方で拒否する。`cursor.globs` があるときは文字列か null であり、null は globs なしを意味する。`cursor.alwaysApply` があるときは真偽値である。`body.md` が存在すること。不正が1件でもあれば異常終了し、出力ファイルは書かれない
- `rules.ja` 自体が無いときも異常終了し、何も書かない
- エラー表示はルール名・原因・次のアクションの形。`rules.ja` が無いときは、同じ形で名前を `rules.ja` とする。終了コードで成否を返す

実装：Python 3、標準ライブラリのみ、単一ファイル（拡張子なし）。JSON は標準の `json` で読み、frontmatter の値はクォートなしの plain scalar で出力し、キー順は description、globs、alwaysApply として現行の .mdc に合わせる。Mac／Windows の両方で動くことを前提とする。

テスト：テストファーストで作る。フィクスチャ3ケース（alwaysApply／globs／description のみ）のゴールデン比較、実ルールの凍結スナップショットによる回帰（入力と期待出力を 2026-11-21 に `scripts/tests/fixtures/real/` へ凍結したもの。オラクルはスナップショットであり、現行の生成物ではない）、出力報告の検証（要約行の全文と、実行が書いた／検査した全パス）、`--check` のケース（一致、手編集、兄弟が残った状態でのファイル1件の欠落、出力ディレクトリの欠落・空、無関係なファイルだけが残るディレクトリ）、異常系（欠落・不正・未知キー、object でない `meta.json`、`description` の欠落・非文字列、`cursor` の欠落・非 object、`cursor` 配下の未知キー、非文字列の `globs`、非真偽値の `alwaysApply`、`rules.ja` ディレクトリの欠落、および正常と異常の混在で出力が書かれないこと）。

完了条件：

1. 実ルールの凍結スナップショットに対して、生成物が期待出力とバイト単位で一致する
2. 2回連続実行で2回目の差分がゼロ
3. `--check` が、正本と一致する状態で正常終了し、生成物の手編集・ファイル欠落・出力ディレクトリの欠落／空で異常終了する。名前はズレたファイルを示し、ディレクトリ自体が無い、またはエントリが1つも無いときだけディレクトリを示す。無関係なファイルが残っているディレクトリはそれに当てはまらず、欠けた生成物をそれぞれ名指す
4. 不正な入力で異常終了し、出力ファイルを一切書かない
5. globs を持つフィクスチャで、Claude 版に `paths` frontmatterが正しく出る

## build-skills

目的：`skills.ja/<名前>/` のスキルを、ホームのスキル置き場（`~/.claude/skills/` と `~/.cursor/skills/`）へ、スキルごとに1つのシンボリックリンクとして配置する。リンク先はこのリポジトリ内のスキルディレクトリである。スキルには形式変換が無いため、配置はコピーを作らずリンクだけを作る：実ファイルは正本だけにし、スキルの編集は再配置なしで効く。

入出力の契約：

- 配置の単位はスキルディレクトリである。リンクはその中身すべて（SKILL.md と補助ファイル）をカバーし、スキル内部にファイルが増えても再配置は不要である。再配置が要るのはスキル自体の追加・削除のときだけである
- リンク先は `--root` で与えたリポジトリルート配下の絶対パスである。リポジトリを移動するとリンクは壊れるが、`--check` がそれを報告し、通常実行が修復する
- このスクリプトが管理するのは、このリポジトリの `skills.ja/` を指すシンボリックリンクだけである。実ファイル・実ディレクトリを作る・上書きする・消すことは決してせず、他を指すリンクにも触らない。他者のエントリ（例：`~/.claude/skills/synced/`。Claude Code が利用者の claude.ai アカウントからダウンロードしたスキルを置く場所）は管理対象外である
- スキルの配置を妨げる宛先エントリ（実ファイル・実ディレクトリ、またはこのリポジトリの外を指すリンク）は衝突である。衝突は、何も変更する前に検出する：不正なスキルが1つでもある、または選択した宛先に衝突が1つでもあれば、異常終了し、リンクの作成・修復・除去は一切行わない
- 選択した宛先で、`skills.ja/` の現存しないスキルを指すリンクは、残骸である。通常実行はこれを除去し、`--check` は報告する。除去するのは、このリポジトリ内を指すリンクだけである
- 報告も契約の一部である。通常実行は、要約行（`installed <件数> skills from skills.ja under <ホーム>`）に続けて、配置済みの全リンクのパスを出し、除去した残骸リンクごとに `removed: <パス>` の行を出す。`--check` の成功時は `checked <件数> links from skills.ja under <ホーム>; all match; wrote nothing` に続けて、検査した全パスを出す。無言の成功は欠陥である：何も起きなかったことと区別できない
- `--check` の失敗時は、標準エラーに要約行、問題ごとの行、次のアクション（`run without --check to install the links; conflicting entries must be removed by hand.`）を出す。問題は、オペレータが操作する単位で名前を出す：エントリが無い場合は `missing: <パス>`、リンク先が違う・壊れている場合は `differs: <パス>`、スキルが消えたリンクは `stale: <パス>`、触ってはいけない妨害エントリは `conflict: <パス>`。宛先ディレクトリ自体が無い場合は、配下のリンクを列挙せず、ディレクトリを一度だけ名指す（`missing: <ディレクトリ>`）
- 2回連続実行では、2回目は何も変わらない（冪等）
- `--tool <cursor|claude>` は、実行の対象を一方の宛先に絞る。`cursor` は `<ホーム>/.cursor/skills`、`claude` は `<ホーム>/.claude/skills` である。`--tool` を省くと両方の宛先が選ばれ、これが上のすべての場合である。選ばれなかった宛先はこの実行の対象外である：作らない、中を見ない、報告しない。そこにある衝突や残骸リンクは実行に影響せず、失敗した実行を含め、前後で同一である。`cursor` と `claude` 以外の値は `tool: unknown tool "<値>". pass --tool cursor or --tool claude` で異常終了する。`--tool` を2回以上渡したときは `tool: --tool was given more than once. pass it once` で異常終了する。どちらのエラーも、宛先を読む前・書く前に出し、何も変えない。要約の件数は、通常実行ではスキル数、`--check` ではリンク数のままである。宛先が一方だけのとき、この二つの数は一致し、表示するパスはすべて選択した宛先の下にある

非目標：スキルファイルのコピー、ルールの配置（build-rules が生成し、ホームへの配置は別扱い）、翻訳とスキルの英語版、実ファイル・実ディレクトリの削除、プラグインスキルや claude.ai 同期スキルの管理、監視モード、Windows 対応（シンボリックリンクに特権が要る環境は前提にしない）。

検証とエラー：

- 全スキルの検証を終えてからリンクを始める。`skills.ja` が存在すること。`skills.ja/` の各サブディレクトリがスキルであり、`SKILL.md` を含む。その frontmatter は単純な `key: value` 行として読み、`name` と `description` があり、どちらも空でない文字列で、`name` がディレクトリ名と一致すること。他の frontmatter キーは許可する（スキル形式は開かれた標準で、`disable-model-invocation` のような任意キーがある）。`synced` という名前のスキル（大文字小文字を問わない）は、選択した宛先に `claude` が含まれるときに拒否する：Claude Code が `~/.claude/skills/` で同期スキル用に予約した名前である。`--tool cursor` だけのときは、その名前は通常のスキルである。全スキルが検証を通り、選択した宛先に衝突が無いときにだけリンクを始める
- エラー表示はスキル名・原因・次のアクションの形。`skills.ja` が無いときは、同じ形で名前を `skills.ja` とする。終了コードで成否を返す

実装：Python 3、標準ライブラリのみ、単一ファイル（拡張子なし）、build-rules と同じ流儀。コマンドラインは `build-skills [--root <リポジトリルート>] [--home <ホームディレクトリ>] [--tool <cursor|claude>] [--check]` で、`--home` は既定で利用者のホームであり、テストが一時ホームへ配置できるようにするためのものである。`--tool` は仕様のみで未実装である。frontmatter は単純な `key: value` 行として読み、YAML ライブラリは使わない。対象プラットフォームは macOS である。

テスト：テストファーストで、build-rules のテストと同じ流儀（スクリプトをサブプロセスとして、一時的な `--root` と `--home` に対して実行する）。ケースは、新規配置で全スキルが両宛先に正しいリンク先で張られること、2回目の実行で何も変わらないこと、`--check` が配置済み状態で成功し、リンク欠落・リンク先違い・残骸リンク・衝突でパスを名指して失敗し、宛先ディレクトリの欠落ではディレクトリだけを名指すこと、通常実行が残骸リンクを除去しリポジトリ移動で壊れたリンクを修復すること、衝突（宛先の実ディレクトリ）が実行全体を止めて何もリンクされないこと、不正入力（SKILL.md 欠落、description の欠落・空、ディレクトリ名と違う name、`synced` という名前のスキル、`skills.ja` の欠落、正常と異常の混在）で異常終了して何も変わらないこと、スクリプトが所有しないエントリ（実在の `synced/` ディレクトリ、外を指すリンク、実ファイル）が、失敗した実行を含め全ての実行の前後で不変であること、出力報告の検証（要約行の全文と、実行が配置した／検査した全パス）、実物の `skills.ja` を一時ホームへ配置し、現行の全スキルがリンクされ、全リンクが SKILL.md を含むディレクトリへ解決すること（出力はバイト列ではなくリンクであるため、オラクルはゴールデンスナップショットではなく `skills.ja` 自体である）、および `--tool` のケース（cursor のみと claude のみは、その宛先だけにリンクし、もう一方は不変であること、選ばれなかった側の衝突や残骸は実行を止めずそのまま残ること、修復と残骸の除去は選択した宛先だけであること、`--check` は選択した宛先だけを名指すこと、`synced` という名前は claude では拒否され cursor のみでは受け付けること、未知の値と繰り返した `--tool` は上の文面で異常終了し何も変えないこと）。

完了条件：

1. `--tool` を省いたとき、空のホームに対して、`skills.ja` の全スキルが両宛先にリンクされ、全リンクがリポジトリ内のそのスキルディレクトリへ解決する
2. 2回連続実行で、2回目はリンクの作成・修復・除去を一切しない
3. `--check` が、配置済み状態で正常終了し、リンクの欠落・リンク先違い・残骸・衝突でパスを名指して異常終了し、宛先ディレクトリ自体が無いときだけディレクトリを名指す
4. 不正な入力または衝突があるとき、異常終了し、何も変えない：リンクの作成・修復・除去を一切しない
5. スクリプトが所有しないエントリ（実ファイル・実ディレクトリ、このリポジトリの外を指すリンク、`synced/`）は、失敗した実行を含め、全ての実行の前後で同一である
6. `--tool cursor` または `--tool claude` では、その宛先だけをリンクし、検査し、修復し、掃除する。もう一方の宛先は、失敗した実行を含め、前後で同一である。未知の値、または繰り返した `--tool` は、何も変えない

## translate-rules

目的：`rules.ja/`（日本語正本）から公開用英語版 `rules.en/` を生成する。このリポジトリは一般公開するため、リポジトリを読む人向けに英語版を用意する。正本は承認者が直接検証できる日本語に固定する。エージェントが従うのは、build-rules が正本から生成する日本語の配布物である。英語版は生成物とする。

契約：

- 対象は `body.md` と `meta.json` の `description`。`basis.md`（根拠）は承認者が読む文書であり対象外
- 出力は `rules.en/<名前>/body.md` と `rules.en/<名前>/meta.json` のみ。配布は日本語正本から build-rules が行う
- `description` を訳す。`cursor` 名前空間は同じ JSON をコピーする。既に英語の見出しと識別子はそのまま残す
- 翻訳器は Claude Code のコマンド `claude -p` である。スクリプトは日本語の正本と、そのルールが `rules.en/` に既にあるときは前回の英語を渡し、コマンドが標準出力に出した訳文を書く。認証は、そのマシンに既にある Claude Code のログインである
- 正本を更新したときに実行する。対象は `git diff` で `rules.ja/` の変更ファイルから特定し、ルール名の明示指定もできる
- 日本語が変わっていない箇所は、前回の英語を維持する。訳し直すのは、変わった日本語だけである。レビューは `rules.en/` の対象ファイルの差分である
- `claude` が無い、またはコマンドが失敗したときは、その実行は何も書かず、`rules.en/` を実行前のままにする。異常終了し、ルール名・原因・次のアクション（`claude -p` を成功させてから再実行する）を出す

非目標：Google Translate、DeepL、API キーを要する翻訳器。

## この仕様書の持ち方

書くのは「なぜ」と「契約」。振る舞いの細部はテストが、実装方法はコードが正本である。
