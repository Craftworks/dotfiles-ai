# dotfiles-ai

AI 開発環境の設定リポジトリ。Cursor / Claude Code / Muse Code の3者に共有する原則・ルール・スキルの正本とし、各ツールへはここから配置する。正本はリポジトリ直下（ルールは `rules.ja/`、スキルは `skills.ja/`）に置く。ルールはプラットフォーム別ディレクトリ（`.cursor/`、`.claude/`）へ生成し、スキルはリポジトリ内にコピーを持たず、各ツールが読むホームディレクトリの置き場へ直接インストールする。

本 README は英語版が正典であり、`README.ja.md` は同じコミットで同期させる（`scripts/README.md` と `scripts/README.ja.md`、`scripts/SPEC.md` と `scripts/SPEC.ja.md` の各組も同様）。

## 役割分担

- **ユーザー ＝ 承認者**：設計・脆弱性・性能・コストを判断し、証拠（テスト結果、差分、計測）で承認する
- **Cursor ＝ コックピット**：diff を読み、コードを辿り、承認するための窓
- **claude ＝ 職人**：実装とテストを行う
- **muse ＝ 監査**：コードの実装と修正はしない（文書の変更は行う）。レビューの指摘を規約・仕様・決定事項に照らして検証し、採用／却下（理由）／保留に仕分ける。修正の報告はテストの再実行と仕様との照合で裏付ける。決定と状態の記録を保ち、承認の判断材料を揃える

監査の文脈は長くなったらファイルへ落とし込み、セッション自体はいつでも捨てられる運用にする。状態の正本は会話ではなくファイルに置き、状態ファイルへの書き手は監査（muse）に一本化する。

## 原則の共有方法

- **スキル**は Agent Skills 標準（`SKILL.md`）で3者にそのまま共有できる。Claude Code は `~/.claude/skills/`、Cursor は `~/.cursor/skills/` のほか互換パスとして `~/.claude/skills/` も読む
- **ルール**は形式がプラットフォームごとに異なる（Cursor は `.mdc`、Claude Code は `CLAUDE.md` と `paths:` つきルール、muse は素の Markdown）。正本は `rules.ja/` に置く：ルールごとに `body.md`（本文）と `meta.json`（description と、プラットフォーム固有項目を名前空間に分けたもの）に分離している。各形式への生成は `scripts/build-rules` が正本から行い、そのファイルのホームへのリンクは `scripts/install-rules` が行い、スキルのインストールは `scripts/install-skills` が行う。ルールとスキルはホームディレクトリへのインストール（`~/.claude/rules/`、`~/.cursor/rules/`、`~/.claude/skills/`、`~/.cursor/skills/`）から効き、このリポジトリは正本とスクリプトだけを持ち、プロジェクトレベルのルールやスキルは持たない。編集は正本に対して行い、生成物やインストール済みのファイルは編集しない。英語版などの他言語版（`rules.en/` と `skills.en/`）は `scripts/translate-rules` と `scripts/translate-skills` が正本から生成し、正本は日本語のままにする。`scripts/build-rules` と配置スクリプトは `--lang`（既定は `en`）を取り、読む人は自分の言語の版を生成・配置できる

## 運用原則

1. **常駐は痩せさせる**：常駐で読み込まれる指示は「地図＋検証コマンド＋失敗の瘢痕」だけにし、詳細は必要時に読まれる層（スキル、プロジェクト仕様）へ逃がす
2. **足すのは失敗の観測に対してだけ**：エージェントが間違えたら、その場の修正で終わらせず、判断のミスはルール／スキルへ1行、反復作業はスキル化、例外不可の規則はフック等の機械へ、のいずれかに昇格させる
3. **例外不可はプロンプトでなく機械で強制する**：ルール文に「必ず〜せよ」と書きたくなったら、置き場所はフックやリンターである
4. **役は文脈隔離に意味がある場所だけ**：サブエージェントは「並列・出力隔離・未見のレビュアー」が効く場合に限り、自分のワークフローの頻出作業から作る。先に網羅で揃えない
5. **流量を制御する**：承認者がレビュー可能な量を超えて生成させない
