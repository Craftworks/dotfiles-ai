# UI / UX

UI/UX は内部品質（堅牢・速度・保守）より目的側で上位。内部最適化のために操作感や理解しやすさを犠牲にしない。

daemon・CLI 等の制御面と運行の分かりやすさは `operator-ux` スキルを参照する。こちらは**画面プロダクトの見た目と操作感**を扱う。

## 手順（設計とレビューで、この順に確認する）

1. **操作への結果を見せる**：すべての操作に、成功・失敗・進行中のいずれかの結果が見えるようにする。クリック後に無反応な時間を置かない
2. **待ちを沈黙させない**：ローディング、無効化、進捗、スケルトン等で状態を示す
3. **体感性能を優先する**：初回表示、入力応答、遷移の速さを守る。遅い処理は先に UI を更新し、後で確定させる
4. **状態の画面を正式に設計する**：空状態・エラー状態・権限不足を正式な画面として設計する（「何もない」で終わらせない）。エラーはトースト一瞬やコンソールだけに逃がさない
5. **一貫性を保つ**：同じ意味の操作は、同じ見た目・同じ場所・同じ言葉にする
6. **最低限のアクセシビリティを守る**：キーボード・フォーカス・コントラスト・名前付け可能なラベルを確保する

## 反パターン

- クリック後に無反応な時間を置く
- エラーをトースト一瞬やコンソールだけに逃がす
- 装飾やアニメで状態の意味を曖昧にする
- タッチ／クリック領域を小さくしすぎる、または誤タップしやすい配置にする
- 「きれい」のために情報階層やフィードバックを削る

## 出口条件

次を満たしたら完了とする：

- Decision test：**ユーザーが今なにができて、次に何が起きるかが一目で分かるか**
