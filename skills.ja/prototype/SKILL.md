# Prototype

プロトタイプとは、**疑問に答えるための捨てコード**である。疑問が形を決める。

## 分岐を選ぶ

答えようとしている疑問がどちらかを見極める。ユーザーのプロンプト、周囲のコード、または（ユーザーがいれば）質問で判断する：

- **「このロジック／状態モデルの感触は正しいか？」** → [LOGIC.md](LOGIC.md)。単一の共有可能な HTML ファイル（自由に押せるボタン＋タブ式のガイド付きウォークスルー）を作り、紙の上では推論しにくいケースを状態マシンに通す。非開発者でも操作できる形にする
- **「これはどう見えるべきか？」** → [UI.md](UI.md)。1つのルート上に根本的に異なる UI バリエーションを複数生成し、URL の検索パラメータと画面下部のフローティングバーで切り替える

2つの分岐は全く違う成果物を生むので、ここを間違えるとプロトタイプ全体が無駄になる。疑問が本当に曖昧でユーザーに確認もできない場合は、周囲のコードに合う方の分岐を既定にする（バックエンドのモジュール → ロジック、ページやコンポーネント → UI）。その前提はプロトタイプの先頭に明記する。

## 両分岐に共通するルール

1. **初日から捨て前提で、そのことが分かるように標識する。** プロトタイプのコードは、実際に使われる場所の近く（対象のモジュールやページの隣）に置いて文脈を明らかにする。ただし、ざっと読んだ人がプロトタイプだと分かる名前を付ける。捨て UI ルートはプロジェクト既存のルーティング規約に従い、新しいトップレベル構造を発明しない
2. **起動が自明であること。** UI プロトタイプはプロジェクトのタスクランナーの1コマンドで起動する（`pnpm <name>`、`python <path>`、`bun <path>` 等）。ロジックデモはダブルクリックで開く単一 HTML ファイル。どちらも、起動に思考を要しない
3. **既定では永続化しない。** 状態はメモリに置く。永続化はプロトタイプが**検証する対象**であって、依存するものではない。疑問が明示的にデータベースに関わる場合は、スクラッチ DB か「PROTOTYPE, wipe me」と分かる名前のローカルファイルを使う
4. **磨き込みを省く。** テストなし、プロトタイプを**動かす**のに必要な範囲を超えるエラー処理なし、抽象化なし。目的は速く学ぶことである
5. **状態を表面に出す。** アクションのたび（ロジック）、バリエーション切替のたび（UI）に、関連する状態の全体を出力／描画し、何が変わったかユーザーが見えるようにする
6. **終わったら保存する。** 検証された決定は本物のコードに取り込み、プロトタイプ自体は**一次資料**として保存する：main の外の捨てブランチにコミットし、そのブランチへのポインタを作業記録（タスクのファイルやコミットメッセージ）に残す。答え自体（判定と、それが決着させた疑問）も作業記録かコミットに残す。main ブランチに残るのは検証された決定だけである
