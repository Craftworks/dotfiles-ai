# Performance

## Do

- 最適化の前にボトルネックを特定する（計測・プロファイラ・ログ・簡易ベンチ）
- ホットパスを短く保つ。割り当て・コピー・ロック・同期I/Oを意識する
- N+1、重複フェッチ、不要な再レンダー/再計算を先に潰す
- 複雑度（時間・空間・往復回数）を変更理由に含める
- キャッシュは無効化条件と寿命をセットで入れる

## Don't

- 計測なしの「速そう」リライト
- 読みにくさを増やすだけの微最適化
- 全体を非同期/並列にするだけで直した気になる
- 無制限キャッシュ、またはキー設計のないメモ化

## Default order

1. 正しさ
2. 明瞭さ
3. 実測されたボトルネックの除去
4. 必要ならアルゴリズム/データ構造の変更
