# scripts ディレクトリ仕様（SPEC）

この SPEC は scripts ディレクトリの仕様書である。

ルールとスキルの言語版を処理するスクリプトを置く：`build-rules`、`install-rules`、`install-skills`、`translate-rules`、`translate-skills`（すべて実装済み）。正本は `rules.ja/` と `skills.ja/` で、他の版（例えば `rules.en/` と `skills.en/`）は翻訳スクリプトが正本から生成する。各スクリプトの目的とオプションは `--help` にある。

全スクリプト共通（以降の節では繰り返さない）：

- 各スクリプトは拡張子なしの Python 3 標準ライブラリのみのファイルで、自分を含むリポジトリに対して働く。build-rules と翻訳スクリプトは Mac と Windows で動く。配置スクリプトはシンボリックリンクを使うので macOS のみ
- 版のディレクトリが存在する言語なら何でも選べる（`--lang`、または `--from` と `--to`。この2つは別の言語でなければならない）。言語コードは英数字、`-`、`_` のみで、リポジトリの外へ出る値は通らない。不正な言語コード、オプションの重複指定、未知のオプション値は、何かを読み書きする前にエラーにする
- 失敗した実行は何も書かず、作らず、直さず、消さない。最初の変更の前に入力をすべて検証する。エラーは対象の単位（ルール、スキル、ファイル）、原因、次の行動を示す。文言の厳密な形はテストが固定する
- 報告は契約の一部である。通常の実行は要約と、書いた／リンクした全パスを出し、成功した `--check` は何を確認したかと、何も書かなかったことを出す。成功が無言なのは欠陥である（何も起きなかったのと区別できない）。失敗した `--check` は、問題を操作者が動く単位で名指しし、ディレクトリが無い／空のときはそのディレクトリを1回だけ名指しする
- 自分の出力に対して再実行しても何も変わらない（冪等）
- ルールの生成と配置は、同じ `--lang` で続けて行う。配布物は、どの言語から作ったかを記録しないため
- 振る舞いの細部（エラー文面、報告形式、ケース）はコードが表し、`scripts/tests/` のテストが独立に照合する。テストは一時リポジトリの中で各スクリプトをサブプロセスとして実行する。共有モジュールは直接テストする。自動テストは本物の `claude` を呼ばない

## build-rules

目的：`rules.<lang>/<名前>/` から `.cursor/rules/<名前>.mdc` と `.claude/rules/<名前>.md` を生成する。

契約：

- 入力は選んだ版だけ。出力は入力の純関数で、同じ入力は常に同じバイト列になる
- 生成物に印のヘッダは付けない。正本とのずれは、ファイル内の文字ではなく `--check` で検出する
- 先にすべてのルールを `scripts/rule_source.py`（translate-rules と共有）で検証する。ルールは両方で有効か、両方で無効かのどちらか

非目標：翻訳、ホームへの配置、git 操作、監視モード、差分処理。

注：Claude Code のルール読み込みは frontmatter の `paths` だけを見る。`alwaysApply` は読まない。`~/.claude/rules/` に置いたファイルは常駐で読まれる。自動ルール（description のみ）をホーム側でどう扱うかは、配置設計の未決事項（実測で確認待ち）。

完了条件：

1. 実ルールの凍結スナップショット（`scripts/tests/fixtures/real/`。日本語の正本を持つ）に対して、生成物が期待出力とバイト単位で一致する
2. `--check` は、出力が一致すれば正常終了し、手で編集された、欠けた、無い出力ではエラーで終了する
3. 不正な入力ではエラーで終了し、出力ファイルを一切書かない
4. globs を持つ fixture では、Claude 版の frontmatter は `paths` であり、その globs の文字列をただ1つのリスト項目として持つ

## install-skills と install-rules

目的：`skills.<lang>/<名前>/` のスキル（install-skills）、または `build-rules` が書いた配布物（install-rules）を、Cursor と Claude のホームの置き場へ、スキルまたはファイル1つにつきシンボリックリンク1本として配置する。コピーも生成もしないので、リポジトリだけが実体で、元を編集すれば再配置なしで反映される。`--tool` は実行を片方の配置先に絞る。選ばれなかった側は作らず、読まず、報告せず、そこにある問題は実行に影響しない。

契約：

- スクリプトが所有するのは、このリポジトリの中を指すシンボリックリンクだけ：install-skills は任意の `skills.<lang>/`、install-rules は `.cursor/rules/` か `.claude/rules/` の配布物。実ファイルや実ディレクトリを作らず、上書きせず、消さない。他を指すリンクにも触れない。他者が持つエントリ（例：Claude Code がユーザーの claude.ai アカウントから同期したスキルを置く `~/.claude/skills/synced/`）は管理の外
- リンク先はリポジトリ配下の絶対パス。リポジトリを動かすとリンクは壊れる。`--check` が報告し、通常の実行が直す
- リンクの邪魔をする配置先のエントリ（実ファイル／実ディレクトリ、またはスクリプトが所有しないものを指すリンク）は衝突である。衝突は何かを変更する前に検出する
- スクリプトが所有するリンクで、元が選んだ版にもう無いものは古い（stale）。通常の実行は消し、`--check` は報告する。リポジトリのファイルは残す
- install-skills：選んだ版とは別の版を指すリンクは、通常の実行が直し、`--check` は `differs` と報告する。`skills.<lang>` 直下のサブディレクトリはすべてスキルで、`scripts/skill_source.py`（translate-skills と共有）で検証する。frontmatter は単純な `key: value` の行として読む（YAML ライブラリは使わない）。`synced` というスキル（大文字小文字を問わない）は、`claude` が選ばれた配置先のときは拒否する（Claude Code がその名を予約しているため）。`--tool cursor` だけのときは普通のスキル
- install-rules：ルールの集合は `rules.<lang>/` のサブディレクトリ。選んだ各配置先に、そのルールの配布物が既に存在していなければならない。無ければ `build-rules` を実行するよう促すエラー

非目標：ファイルのコピー、実ファイルや実ディレクトリの削除、プラグインのスキルや claude.ai 同期スキルの管理、翻訳、監視モード、Windows 対応。install-skills はルールを配置せず、install-rules は配布物を生成も削除もしない。

完了条件：

1. 空のホームへ実行すると、選んだ版のすべてのスキルまたはルールが両方の配置先にリンクされ、各リンクはリポジトリの中に解決する
2. 続けて2回実行しても、2回目は何も作らず、直さず、消さない
3. `--check` は配置済みの状態で正常終了し、リンクの欠け、誤ったリンク、古いリンク、衝突ではパスを名指ししてエラーで終了し、配置先ディレクトリ自体が無いときはディレクトリだけを名指しする
4. 不正な入力、元の欠け、衝突があればエラーで終了し、何も変更しない
5. スクリプトが所有しないエントリは、失敗した実行も含め、どの実行の前後でも同一
6. `--tool` を指定したとき、もう一方の配置先は、失敗した実行も含め前後で同一

## translate-rules と translate-skills

目的：ルール版 `rules.<from>/`（またはスキル版 `skills.<from>/`）を `<to>` へ翻訳する。どの版が存在するかと、エージェントがどれに従うかは別の選択で、生成と配置の `--lang` が決める。これらのスクリプトは翻訳だけを行う。

契約：

- translate-rules の対象は `body.md` と `meta.json` の `description`。`cursor` 名前空間は同じ JSON のままコピーし、翻訳しない。`cursor` だけが変わったときは、翻訳コマンドを呼ばずに `meta.json` を書き直す。`basis.md` は承認者向けの文書で、どちらのスクリプトでも対象外
- translate-skills は Markdown ファイル1つを1回の呼び出しで送る（`SKILL.md` は `description` と本文を翻訳し、`name` はディレクトリ名のまま、他の frontmatter はコピーする）。長くまとめたリクエストは行の契約の範囲外。Markdown でないファイルはバイト単位でコピーし、呼び出さない。コードフェンス内の行も送る
- 行の契約：訳文は、原文の1行につきちょうど1行を、同じ順序で持ち、各行の Markdown の記号を保ち、句読点は原文に従う。コードフェンス内の原文言語のテキスト（コメントを含む）は翻訳し、コードのトークンと文字列リテラルは残す。テキストと見出しは、すでに訳文の言語であるものだけをそのまま残し、識別子は常にそのまま残す。この契約があるから、前回の訳文を残す処理が機械的にできる。定義は `scripts/translator.py` にあり、モデルとプロンプトの唯一の定義でもある
- 基準は保存したコピーではなく git から取る。基準コミットは訳文を最後に変えたコミット（`rules.<to>/<名前>/body.md`、スキルではファイルごとの `skills.<to>/<スキル>/<パス>`）。前回の原文と訳文は同じそのコミットから読むので、対が常に行単位で一致する。訳した版は、訳した後にコミットされている必要がある。レビューもそのときに行う
- ルールまたはファイルが対象になるのは、原文が前回の原文と異なるとき、または訳文が存在しないとき（その場合は全文を翻訳する）。コマンドラインの名前は実行を絞る。未知の名前はエラー
- 原文が変わっていない箇所は、前回の訳文をバイト単位で保つ。翻訳コマンドには、現在の原文全体と、用語を揃えるために、変わっていない行の前回の訳文だけを [原文, 訳文] の対として渡す。変更された行の古い訳文は決して見せない。見せると、モデルが新しい原文を訳さず古い行をそのまま写すため
- 訳文側に未コミットの変更がある場合と、基準の対の行数が食い違う場合はエラー。訳文を消せば全文翻訳になる。黙って全文を再翻訳することはしない
- 翻訳器は Claude Code のコマンド `claude -p`（Sonnet モデル）で、マシンにすでにあるログインを使う（`--bare` は使わない。`ANTHROPIC_API_KEY` しか読まず、ログインを読まない）。隔離して動かす：作業ディレクトリは空の一時ディレクトリで、CLAUDE.md、ルール、フック、MCP サーバー、スキル、ツールは読み込まれない
- リクエストと回答は、文字列の `description` と、1行につき1文字列の配列 `body` を持つ JSON オブジェクト（素の行だと、モデルが description をタイトル見出しに混ぜてしまう）
- 呼び出しが失敗とされ、再試行されないのは、翻訳器が無い、非ゼロで終了する、タイムアウトする（タイムアウトした翻訳器は子プロセスごと止める。止められなければ、エラーがそのプロセスを名指しする）、または出力が契約を破る（空または不正な出力、行数や Markdown の記号の違い、原文言語の文字の残り、空の description）とき
- 書き込みの前に、すべての対象を翻訳して検証する。どれか1つでも失敗したら訳文の版は元のままなので、再実行しても安全。ファイルは一時ファイルを経由して置き換えるので、中断した実行が書きかけのファイルを残さない。原文は呼び出しの前に検証する
- translate-rules はルール1つにつき1回、1つずつ呼び出す。translate-skills は `--jobs` 個ずつ並行して呼び出す。失敗すると、実行中の呼び出しを止め、新しい呼び出しを始めない。止められなかったプロセスは、次の行動（手で止める）とともに名指しする
- 進捗は進むごとに、ルールまたはファイル1つにつき1行出す。実行が1分以上かかるため。対象のない実行は、その旨を言って何も書かない

非目標：Google 翻訳、DeepL、API キーを必要とする翻訳器すべて、原文が消えたときの `<to>/<名前>/` の削除（手で行う）、リポジトリを変更する git 操作（履歴を読むだけで、コミットは利用者が行う）、版の配置、translate-rules での並列呼び出し、監視モード。

完了条件：

1. 変更されたルールまたはファイルは、変わっていない原文の各行が前回の訳文をバイト単位で保った訳文を生む
2. 原文に変更がなければ、実行は翻訳コマンドを呼ばず、何も書かない
3. 失敗した呼び出しや不正な入力では、単位、原因、次の行動を示すエラーで終了し、訳文の版は前後で同一
4. 翻訳器は CLAUDE.md、ルール、フック、MCP サーバー、スキル、ツールなしで起動する
5. Mac と Windows の両方で動く

## この仕様書の持ち方

書くのは「なぜ」と「契約」。振る舞いの細部はコードが表し、テストが独立に照合する。
